01Generics — Satu Algoritma, Banyak Tipe

Generic memungkinkan Anda menulis fungsi atau tipe yang bekerja untuk tipe apa pun, dengan compiler tetap mengecek tipe secara penuh. Tidak ada casting, tidak ada Any, tidak ada kehilangan keamanan.

Generic function & generic type
// Generic function — `T` adalah type parameter
func swapValues<T>(_ a: inout T, _ b: inout T) {
    let tmp = a; a = b; b = tmp
}

// Generic type — Stack bekerja untuk Element apa pun
struct Stack<Element> {
    private var items: [Element] = []
    var isEmpty: Bool { items.isEmpty }
    mutating func push(_ item: Element) { items.append(item) }
    mutating func pop() -> Element? { items.popLast() }
}

var s = Stack<Int>()      // di-specialize jadi Stack of Int — nol overhead
s.push(1); s.push(2)
s.pop()                    // Optional(2)
Kenapa cepatCompiler melakukan monomorphization / specialization: Stack<Int> menghasilkan kode mesin khusus Int, seolah Anda menulisnya manual. Berbeda dari Java generics (type erasure) atau existential Swift — generic Swift tidak punya biaya boxing.

02Type Constraints & where

Generic tanpa constraint hanya bisa melakukan hal yang berlaku untuk semua tipe (assign, simpan). Untuk memanggil method, batasi T dengan protocol.

// Constraint: T harus Comparable agar bisa pakai operator <
func maxElement<T: Comparable>(_ items: [T]) -> T? {
    items.max()
}

// `where` clause untuk constraint yang lebih kaya
extension Array where Element: Numeric {
    func total() -> Element { reduce(.zero, +) }
}
[1, 2, 3].total()          // 6
["a", "b"].total()         // compile error — String bukan Numeric

// Constraint pada associated type lewat where
func allEqual<C: Collection>(_ c: C) -> Bool where C.Element: Equatable {
    guard let first = c.first else { return true }
    return c.allSatisfy { $0 == first }
}
Prinsip DesainTambahkan constraint seminimal mungkin tetapi secukupnya. Constraint yang terlalu longgar membuat body tak bisa apa-apa; terlalu ketat membatasi reusability. Idiom Swift: constrain ke protocol kemampuan (Equatable, Hashable, Comparable), bukan ke tipe konkret.

03Associated Types — Generic untuk Protocol

Protocol tidak bisa punya type parameter <T>. Sebagai gantinya, ia mendeklarasikan associated type — placeholder yang diisi oleh tiap conformer. Ini fondasi Repository, Collection, dan hampir semua abstraksi data di iOS enterprise.

Protocol with associated type (PAT)
protocol Repository {
    associatedtype Entity                      // placeholder
    func fetch(id: String) async throws -> Entity
    func save(_ entity: Entity) async throws
}

struct UserRepository: Repository {
    typealias Entity = User                    // sering diinferensikan otomatis
    func fetch(id: String) async throws -> User { /* ... */ }
    func save(_ entity: User) async throws { /* ... */ }
}

Primary associated types (Swift 5.7+)

Old → New · Constraining PAT di tipe
Old 
// Harus pakai generic +
// where — verbose
func use<R: Repository>(_ r: R)
   where R.Entity == User {}
New (5.7+) 
// Tandai primary
protocol Repository<Entity> {…}
// lalu ringkas:
func use(_ r: some Repository<User>){}
let r: any Repository<User>
Migrasi & alasan: Tandai associated type utama di sudut kurung protocol (protocol Repository<Entity>). Ini memungkinkan sintaks lightweight some Repository<User> / any Repository<User>. Alasan perubahan: sebelum 5.7, PAT tidak bisa dipakai sebagai existential sama sekali (any Repository error). Primary associated types membuka ekspresivitas generic standard-library (mis. any Collection<Int>) untuk kode Anda.

04Protocol-Oriented Programming

POP menggantikan inheritance dengan komposisi protocol + default implementation via protocol extension. Tipe value (struct/enum) yang tak bisa inherit pun mendapat shared behavior.

Protocol extension = default behavior
protocol Animal { var name: String { get } }

extension Animal {
    func describe() -> String { "Hewan bernama \(name)" }   // default
}

struct Cat: Animal { let name: String }
Cat(name: "Mochi").describe()   // gratis, tanpa duplikasi

Composition over inheritance

protocol Identifiable2 { var id: String { get } }
protocol Timestamped { var createdAt: Date { get } }
protocol Auditable: Identifiable2, Timestamped {}   // komposisi

// Satu tipe conform ke banyak kapabilitas kecil — bukan satu superclass gemuk
struct Invoice: Auditable {
    let id: String
    let createdAt: Date
}
Tipe memilih kapabilitas yang dibutuhkan, bukan terjebak satu rantai pewarisan.
Anti-PatternMembuat class BaseViewModel raksasa yang diwarisi semua view model adalah jejak OOP yang harus dihindari di Swift. Pecah jadi protocol kecil (Loadable, Refreshable) + protocol extension. Inheritance class hanya untuk kasus yang benar-benar butuh (UIKit, identity).

05some vs any — Opaque vs Existential

Keputusan yang paling sering salah. Keduanya menyembunyikan tipe konkret, tetapi mekanisme dan biayanya berbeda fundamental.

some P (opaque)any P (existential)
Tipe konkretSatu, tetap, diketahui compilerBisa beda-beda saat runtime
MekanismeStatic dispatch, no boxBoxed, dynamic dispatch
BiayaNol overheadHeap box + indirection
Heterogen arrayTidak bisaBisa ([any P])
Default pilihan✓ Mulai dari siniHanya saat butuh heterogenitas
 
// some — return satu tipe konkret yang disembunyikan (API boundary bersih)
func makeRepo() -> some Repository { UserRepository() }

// any — simpan campuran tipe berbeda dalam satu koleksi
let handlers: [any EventHandler] = [LoginHandler(), LogoutHandler()]
for h in handlers { h.handle() }   // dynamic dispatch
Old → New · Existential wajib eksplisit
Old (Swift 5.5−) 
// Existential implisit —
// biaya tersembunyi
let repo: Repository = …
func f(x: Animal) {}
New (Swift 6) 
// `any` wajib —
// biaya jadi terlihat
let repo: any Repository = …
func f(x: some Animal) {}
Migrasi: Tambahkan any ke setiap existential. Untuk parameter, ganti ke some bila tiap call-site memakai satu tipe konkret. Alasan: di Swift 6 language mode, penggunaan existential telanjang menjadi error/warning. Apple sengaja membuat biaya boxing terlihat di kode agar engineer memilih sadar antara fleksibilitas (any) dan performa (some/generic).

06Result & Error Flow

throws adalah idiom utama (Module 1). Result dipakai ketika error perlu disimpan sebagai nilai — melewati batas callback, disimpan di state, atau dikumpulkan.

enum NetworkError: Error { case offline, decoding, server(Int) }

func load() async -> Result<[Order], NetworkError> {
    do {
        let orders = try await api.orders()
        return .success(orders)
    } catch {
        return .failure(.offline)
    }
}

switch await load() {
case .success(let orders): show(orders)
case .failure(let err):    handle(err)
}

// Interop dua arah dengan throws:
let value = try result.get()                 // Result → throws
let r = await Result { try await api.user() } // throws → Result (Swift 6+)
Kapan Result, kapan throwsthrows untuk alur sinkron/async langsung yang ditangani di tempat. Result ketika nilai-error harus hidup di luar stack: disimpan di @Observable state, dikirim lewat closure lama, atau di-map/flatMap sebagai data. Jangan campur keduanya tanpa alasan — pilih satu per boundary.

07Advanced Closures — Capture, Escaping, Sendable

Closure adalah reference type yang meng-capture lingkungannya. Memahami semantik capture adalah prasyarat memahami memory (Module 3).

Capture by reference vs capture list
var counter = 0
let inc = { counter += 1 }    // capture `counter` BY REFERENCE
inc(); inc(); print(counter)  // 2

// Capture list — ambil snapshot nilai saat closure dibuat
var x = 10
let printX = { [x] in print(x) }  // snapshot 10
x = 99
printX()                          // tetap 10

@escaping & retain cycle

final class Downloader {
    var onDone: (() -> Void)?           // disimpan → escaping

    func start() {
        // [weak self] mencegah retain cycle saat closure disimpan
        fetch { [weak self] in
            guard let self else { return }
            self.finish()
        }
    }
    func finish() {}
}
@Sendable closure (Swift 6)Saat closure menyeberang isolation domain (mis. masuk Task atau actor), compiler mewajibkannya @Sendable — tidak boleh meng-capture mutable shared state non-Sendable. Ini ditegakkan sebagai compile error di Swift 6 language mode. Mekanika lengkap concurrency dibahas di Module 3.
func schedule(_ work: @Sendable @escaping () -> Void) {
    Task { work() }
}

08Latihan

EX 01

Generic + constraint

Tulis fungsi generic frequency(of:in:) yang menghitung kemunculan sebuah elemen di array. Pilih constraint yang tepat.

▸ Lihat solusi & review 
func frequency<T: Equatable>(of value: T, in array: [T]) -> Int {
    array.filter { $0 == value }.count
}

Review: Constraint Equatable (bukan Hashable) sudah cukup — Anda hanya butuh ==. Memilih constraint paling longgar yang memenuhi kebutuhan = desain generic yang benar.

EX 02

some vs any

Untuk tiap kasus, pilih some atau any dan jelaskan: (a) factory yang selalu mengembalikan JSONDecoderStrategy; (b) array berisi campuran PaymentMethod (card, wallet, transfer).

▸ Lihat solusi & review

(a) some → func makeStrategy() -> some DecoderStrategy. Satu tipe konkret, sembunyikan dari caller, nol overhead.

(b) any → [any PaymentMethod]. Heterogen, tipe berbeda dalam satu koleksi memerlukan existential. Biaya boxing di sini memang diperlukan dan dapat dibenarkan.

EX 03

Refactor inheritance → POP

Diberi class BaseService dengan method log() yang diwarisi AuthService & PaymentService. Refactor ke pendekatan protocol-oriented.

▸ Lihat solusi & review 
protocol Logging {}
extension Logging {
    func log(_ msg: String) { print("[\(Self.self)] \(msg)") }
}
struct AuthService: Logging {}
struct PaymentService: Logging {}

Review: log() kini default implementation di protocol extension. Service menjadi struct (value type) tanpa kehilangan shared behavior, dan tidak terikat satu superclass.

EX 04

Repository generic

Definisikan protocol Repository dengan primary associated type, lalu tulis fungsi syncAll yang menerima some Repository<Order>.

▸ Lihat solusi & review 
protocol Repository<Entity> {
    associatedtype Entity
    func fetchAll() async throws -> [Entity]
}

func syncAll(from repo: some Repository<Order>) async throws -> [Order] {
    try await repo.fetchAll()
}

Review: some Repository<Order> jauh lebih ringkas daripada generic <R: Repository> where R.Entity == Order, dan tetap nol overhead.
