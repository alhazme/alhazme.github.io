MODULE 03 · PHASE 1 — CONCURRENCY & MEMORYModel Concurrency Modern & Baseline 2026

Ini modul paling banyak berubah dalam dua tahun terakhir. Pendekatan era Swift 5 (DispatchQueue, completion handler) sebagian besar sudah digantikan structured concurrency yang aman secara compile-time.

Swift 6.4Xcode 27~110 menitData-race safe
Baseline Project Xcode 27Project app baru di Xcode 27 default ke tiga setelan ini (warisan Swift 6.2 "Approachable Concurrency"):
  • Default Actor Isolation = MainActor — setiap deklarasi implisit @MainActor kecuali ditandai nonisolated/@concurrent
  • Approachable Concurrency = Yes — termasuk nonisolated(nonsending)
  • Strict Concurrency Checking = Complete — potensi data race jadi compile error
Efeknya: app Anda single-threaded by default — semua di main actor sampai Anda secara eksplisit memilih keluar.

Pergeseran besar dari era sebelumnya:

01async / await

Fungsi async bisa menunda (suspend) di titik await tanpa memblokir thread. Kode asinkron jadi terbaca selinear kode sinkron.

Old → New · Asynchronous call
Old — completion handler 
func loadUser(
  _ done: @escaping (Result<User,Error>)
            -> Void) {
  api.get { r in
    switch r {
    case .success(let u): done(.success(u))
    case .failure(let e): done(.failure(e))
    }
  }
}
New — async/await 
func loadUser() async throws -> User {
    try await api.get()
}

// call-site:
let user = try await loadUser()
update(user)   // sudah di MainActor
Migrasi: Bungkus API callback lama dengan withCheckedThrowingContinuation, lalu ekspos sebagai async. Alasan perubahan: completion handler tidak bisa dijamin dipanggil tepat sekali, sulit dikomposisi, dan rawan "pyramid of doom". async/await memberi alur linear, error handling via try, dan integrasi dengan cancellation.
Memanggil async dari konteks sinkron
// `Task` adalah jembatan dari sync ke async
Button("Muat") {
    Task {
        let user = try? await loadUser()
        self.user = user
    }
}
Suspension pointSetiap await adalah titik di mana state bisa berubah (fungsi lain bisa jalan). Jangan asumsikan invariant tetap sama sebelum dan sesudah await — baca ulang state penting setelah suspend. Ini sumber bug "actor reentrancy" yang dibahas di bagian Actors.

02Structured Concurrency

"Structured" berarti task hidup dalam scope yang jelas: child task tidak bisa hidup lebih lama dari parent, dan cancellation merambat otomatis. Ini mencegah task bocor.

async let — paralel, lalu gabung
func loadDashboard() async throws -> Dashboard {
    async let orders = api.orders()      // mulai paralel
    async let profile = api.profile()    // mulai paralel
    // keduanya berjalan bersamaan; await menggabungkan hasil
    return try await Dashboard(orders: orders, profile: profile)
}
Task group — jumlah task dinamis
func fetchAll(ids: [String]) async throws -> [Order] {
    try await withThrowingTaskGroup(of: Order.self) { group in
        for id in ids { group.addTask { try await api.order(id) } }
        var result: [Order] = []
        for try await order in group { result.append(order) }
        return result
    }
}

Cancellation

let task = Task {
    for id in ids {
        try Task.checkCancellation()    // hormati pembatalan
        await process(id)
    }
}
task.cancel()                            // merambat ke child task
Anti-PatternTask.detached memutus rantai structured — ia tidak mewarisi isolation, priority, maupun cancellation parent. Gunakan hanya saat Anda benar-benar butuh task yang lepas. Default selalu Task { } biasa atau structured (async let / task group).

03Actors & @MainActor

actor adalah reference type yang melindungi state mutable-nya dari akses konkuren. Compiler menjamin hanya satu task mengakses state actor pada satu waktu — pengganti lock manual.

actor BalanceStore {
    private var balance = 0
    func deposit(_ amount: Int) { balance += amount }   // terisolasi
    func current() -> Int { balance }
}

let store = BalanceStore()
await store.deposit(100)     // panggilan lintas-actor bersifat async
let b = await store.current()

@MainActor — actor global untuk UI

@MainActor
final class HomeViewModel {
    private(set) var items: [Order] = []      // dijamin dimutasi di main thread
    func load() async {
        let fetched = try? await api.orders()  // boleh await off-main di dalamnya
        items = fetched ?? []                  // kembali ke main otomatis
    }
}
Actor ReentrancySaat method actor mencapai await, ia melepas isolasi sementara — task lain bisa masuk dan mengubah state. Setelah await, verifikasi ulang precondition. Contoh bug: cek "belum ada cache" → await fetch → simpan, tetapi task kedua sudah mengisi cache di sela await. Solusi: cek ulang setelah suspend, atau gunakan flag in-flight.

04Isolation Defaults — Perubahan Terbesar 2026

Dengan Default Actor Isolation = MainActor, semua kode Anda implisit @MainActor. Anda memilih keluar, bukan memilih masuk. Tiga alat untuk keluar:

AnotasiEfekPakai untuk
nonisolatedLepas dari isolasi actor (sinkron, tak terikat main)Pure function, computed property tanpa state
@concurrentJalan di thread pool global (paralel sejati)Kerja berat CPU-bound (parsing besar, image processing)
nonisolated(nonsending)async func mewarisi isolasi pemanggilDefault Approachable Concurrency — biasanya otomatis
Old → New · Perilaku nonisolated async function
Old (pre-6.2) 
// nonisolated async SELALU
// lompat ke global executor —
// sering memicu error
// data-race tak terduga
func parse() async -> Model {…}
New (6.2+ Approachable) 
// nonisolated async MEWARISI
// isolasi pemanggil.
// Untuk paksa paralel:
@concurrent
func parse() async -> Model {…}
Migrasi: Aktifkan Approachable Concurrency. Fungsi async yang dulu otomatis off-main kini tetap di konteks pemanggil; tandai eksplisit @concurrent jika memang ingin paralel. Alasan perubahan: perilaku lama membuat penulisan async method pada class tanpa error data-race sangat sulit, dan memaksa developer pemula berhadapan dengan executor terlalu dini. Model baru = "single-threaded sampai Anda minta paralel", jauh lebih intuitif dan tetap aman.
Contoh kombinasi
@MainActor
final class ImportViewModel {
    func run(_ url: URL) async {
        let raw = try? await load(url)        // tetap di main (cepat, I/O await)
        let parsed = await Self.parse(raw)    // offload berat ke pool
        self.items = parsed                   // balik ke main otomatis
    }

    @concurrent                               // CPU-bound → paralel
    static func parse(_ raw: Data?) async -> [Item] { /* heavy */ [] }
}

05Sendable & Data-Race Safety

Sendable menandai tipe yang aman dikirim lintas isolation domain. Di Swift 6 language mode, compiler menolak (error) pengiriman tipe non-Sendable melewati boundary actor/task.

// Value type yang seluruh membernya Sendable → otomatis Sendable
struct Money: Sendable { let cents: Int }

// Class harus dibuktikan aman: immutable atau tersinkronisasi internal
final class Config: Sendable {
    let apiBaseURL: URL                       // semua `let` immutable → aman
    init(apiBaseURL: URL) { self.apiBaseURL = apiBaseURL }
}

// Closure yang menyeberang domain wajib @Sendable
func schedule(_ work: @Sendable @escaping () -> Void) { Task { work() } }
Swift 6.4 — ~Sendable & weak letSwift 6.4 menambah ~Sendable untuk secara eksplisit menyatakan sebuah tipe tidak Sendable (menekan inferensi), dan weak let agar referensi weak bisa immutable. Keduanya membuat adopsi Sendable lebih presisi. Untuk app code umum, andalkan inferensi otomatis; gunakan penanda eksplisit hanya saat compiler butuh kejelasan.
Anti-PatternMenambahkan @unchecked Sendable untuk "mematikan" error compiler tanpa benar-benar menyinkronkan akses adalah cara mengubah compile error menjadi crash runtime yang sulit dilacak. Gunakan @unchecked hanya dengan mekanisme sinkronisasi nyata (lock) dan komentar justifikasi.

06ARC & Memory Management

Swift memakai Automatic Reference Counting — deterministik, bukan garbage collector. Setiap reference type (class, actor, closure) dihitung referensinya; saat count mencapai nol, objek di-deallocate seketika.

ReferenceMenaikkan count?Saat target hilangPakai untuk
strong (default)Ya—Kepemilikan normal
weakTidakJadi nil (harus optional)Relasi balik, delegate, parent
unownedTidakDangling (crash jika diakses)Target dijamin hidup ≥ pemilik
Retain cycle & cara memutusnya
final class Customer { var card: Card? }
final class Card { unowned let owner: Customer; init(owner: Customer){ self.owner = owner } }
// Card tidak menaikkan count Customer → tidak ada cycle.

// Closure yang disimpan + capture self = cycle klasik
final class Timer2 {
    var tick: (() -> Void)?
    func start() {
        tick = { [weak self] in self?.update() }   // [weak self] memutus cycle
    }
    func update() {}
}
Cycle terjadi saat dua objek saling strong. Satu sisi dibuat weak/unowned untuk memutusnya.
weak vs unownedPakai weak bila target bisa hilang lebih dulu (delegate, parent view) — aksesnya optional dan aman. Pakai unowned hanya bila Anda yakin target hidup selama pemilik hidup (mis. child yang dibuat & dimiliki parent). Salah memilih unowned = crash. Bila ragu, pilih weak.

07Swift Package Manager

SPM adalah build system & dependency manager resmi. Di arsitektur enterprise modular (Module 9), tiap feature/core menjadi package terpisah dengan dependency direction yang dikontrol.

Package.swift
// swift-tools-version: 6.0
import PackageDescription

let package = Package(
    name: "CoreNetworking",
    platforms: [.iOS(.v27)],
    products: [
        .library(name: "CoreNetworking", targets: ["CoreNetworking"])
    ],
    dependencies: [
        .package(url: "https://github.com/Alamofire/Alamofire", from: "5.10.0")
    ],
    targets: [
        .target(
            name: "CoreNetworking",
            dependencies: ["Alamofire"],
            swiftSettings: [
                // Package TIDAK otomatis MainActor — set eksplisit jika perlu
                .defaultIsolation(MainActor.self)
            ]
        ),
        .testTarget(name: "CoreNetworkingTests", dependencies: ["CoreNetworking"])
    ]
)
Penting — isolasi di packageBerbeda dari target app, SPM package baru TIDAK default ke MainActor dan tidak mengaktifkan Approachable Concurrency. Bila package Anda berisi UI/view model, set .defaultIsolation(MainActor.self) di swiftSettings. Bila berisi networking/logic murni, biarkan nonisolated (default) agar reusable lintas konteks. Ketidaksesuaian setelan inilah penyebab umum error isolasi saat memecah kode ke package.

08Latihan

EX 01

Migrasi completion → async

Ubah API berikut menjadi async throws menggunakan continuation.

func legacyFetch(_ done: @escaping (Result<Data, Error>) -> Void) { /* ... */ }
▸ Lihat solusi & review 
func fetch() async throws -> Data {
    try await withCheckedThrowingContinuation { cont in
        legacyFetch { result in cont.resume(with: result) }
    }
}

Review: resume(with:) menerima Result langsung. Pastikan continuation di-resume tepat sekali di semua jalur — resume ganda = crash, tidak resume = task menggantung selamanya.

EX 02

Paralelkan dua request

Muat profile dan settings secara paralel, gabungkan jadi satu objek. Pakai structured concurrency.

▸ Lihat solusi & review 
func boot() async throws -> Session {
    async let profile = api.profile()
    async let settings = api.settings()
    return try await Session(profile: profile, settings: settings)
}

Review: async let memulai keduanya seketika; await di akhir menunggu keduanya. Jika ditulis let p = try await api.profile(); let s = try await api.settings() keduanya jadi serial — dua kali lebih lambat.

EX 03

Lindungi state dengan actor

Buat TokenStore yang menyimpan token dan aman diakses dari banyak task. Sediakan set dan get.

▸ Lihat solusi & review 
actor TokenStore {
    private var token: String?
    func set(_ t: String?) { token = t }
    func get() -> String? { token }
}

Review: actor menghapus kebutuhan lock manual. Semua akses jadi await store.get(). Jika dibuat class dengan var token, Swift 6 mode akan menolaknya sebagai potensi data race.

EX 04

Temukan & perbaiki retain cycle

Identifikasi cycle dan perbaiki:

final class Feed {
    var onRefresh: (() -> Void)?
    init() { onRefresh = { self.reload() } }
    func reload() {}
}
▸ Lihat solusi & review 
final class Feed {
    var onRefresh: (() -> Void)?
    init() { onRefresh = { [weak self] in self?.reload() } }
    func reload() {}
}

Review: self me-retain closure (onRefresh), closure me-retain self → cycle, Feed tak pernah deinit. [weak self] memutusnya. Verifikasi dengan menambahkan deinit { print("gone") } dan Memory Graph Debugger (dibahas di Module 15).

09Quiz, Mini-Project, Challenge & Referensi

Quiz Cepat

Q1

Actor

Bagaimana actor mencegah data race, dan apa konsekuensinya pada cara memanggil method-nya?

▸ Jawaban

Actor menyerialkan akses ke state mutable-nya (isolation) — hanya satu tugas mengaksesnya pada satu waktu. Konsekuensi: memanggil method actor dari luar bersifat async (await) karena mungkin menunggu giliran. State di dalam actor aman diakses sinkron.

Q2

Sendable

Apa arti Sendable, dan kenapa penting di Swift 6 language mode?

▸ Jawaban

Sendable menandai tipe yang aman dilewatkan antar-konteks konkuren. Di Swift 6 dengan data-race safety, compiler menolak melewatkan tipe non-Sendable melintasi batas isolation — mencegah data race saat kompilasi. Value types immutable umumnya Sendable otomatis.

Q3

Retain cycle

Kapan closure menyebabkan retain cycle, dan bagaimana memutusnya?

▸ Jawaban

Saat closure meng-capture self secara kuat sementara self juga memegang closure itu (mis. stored property). Putus dengan capture list [weak self] (lalu guard let self) atau [unowned self] bila dijamin hidup. ARC tak mendeteksi siklus otomatis.

Mini-Project

Bangun: image loader konkurenBuat actor ImageCache yang menyimpan [URL: Data] dan method image(for: URL) async throws -> Data yang mengembalikan dari cache atau mengunduh (simulasikan dengan delay) lalu menyimpan. Pastikan tak ada data race pada cache. Panggil dari beberapa task paralel dengan async let/TaskGroup. Tujuan: melatih actor isolation, async/await, dan struktur konkuren.

Challenge

Naik levelTambahkan coalescing: bila dua permintaan untuk URL sama datang bersamaan, hanya satu unduhan berjalan dan keduanya menunggu hasil yang sama (hindari unduhan ganda). Tantangan: kelola in-flight tasks di dalam actor (mis. [URL: Task<Data, Error>]) — pola nyata di networking layer (M10).

Common Mistakes

  • Task.detached tanpa alasan — melepas isolation & prioritas konteks. Utamakan Task {} yang mewarisi konteks.
  • Meng-capture self kuat di closure yang disimpan — retain cycle. Pakai [weak self].
  • Membungkus segalanya di actor — over-serialization menurunkan paralelisme. Isolasi hanya state yang benar butuh.
  • Melawan compiler Sendable dengan @unchecked — escape hatch berbahaya; hanya bila Anda menjamin thread-safety manual (mis. actor/lock internal).
  • Mengira @MainActor gratis — memindah kerja berat ke main actor membekukan UI; offload dengan @concurrent/nonisolated.
