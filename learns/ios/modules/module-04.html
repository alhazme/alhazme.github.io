02Struktur Project Production

Struktur folder yang skalabel sejak awal mencegah massive app target. Pendekatan modular memakai SPM lokal (Module 9 memperdalam):

MyApp/
├─ App/                      // entry point, DI container, AppDelegate adaptor
│   └─ MyAppApp.swift
├─ Features/                 // tiap fitur = folder (atau SPM package)
│   ├─ Auth/
│   └─ Orders/
├─ Core/                     // shared: networking, persistence, design system
│   ├─ Networking/
│   └─ Persistence/
├─ Resources/                // assets, localization, Info.plist
└─ Packages/                 // SPM packages lokal (CoreNetworking, DesignSystem)
PrinsipDependency direction selalu mengarah ke dalam: Features → Core → (Foundation/SwiftUI). Fitur tidak boleh saling impor langsung; komunikasi lintas-fitur lewat abstraksi di Core. Ini fondasi Clean Architecture (Module 8).

03App & Scene Lifecycle

Sejak SwiftUI lifecycle, entry point adalah sebuah App yang mengembalikan Scene. State lifecycle diobservasi via scenePhase, bukan callback AppDelegate.

SwiftUI lifecycle — entry point modern
import SwiftUI

@main
struct MyApp: App {
    @Environment(\.scenePhase) private var scenePhase

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
        .onChange(of: scenePhase) { _, phase in
            switch phase {
            case .active:    resumeWork()      // app di depan, interaktif
            case .inactive:  pauseWork()       // transisi (mis. app switcher)
            case .background: persistState()   // di belakang, simpan state
            @unknown default: break
            }
        }
    }
}

Integrasi AppDelegate bila diperlukan

Sebagian SDK (push notification, beberapa analytics) masih butuh hook AppDelegate. Sambungkan tanpa meninggalkan SwiftUI lifecycle:

final class AppDelegate: NSObject, UIApplicationDelegate {
    func application(_ app: UIApplication,
        didFinishLaunchingWithOptions opts: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
        // registrasi push, konfigurasi SDK
        return true
    }
}

@main
struct MyApp: App {
    @UIApplicationDelegateAdaptor(AppDelegate.self) var delegate
    var body: some Scene { WindowGroup { ContentView() } }
}
Old → New · Lifecycle
Old (UIKit) 
// AppDelegate +
// SceneDelegate, banyak
// callback terpisah:
func sceneDidBecomeActive(_:)
func sceneDidEnterBackground(_:)
// window setup manual
New (SwiftUI) 
// @main App + Scene
// state via scenePhase:
.onChange(of: scenePhase){…}
// window dikelola
// WindowGroup
Migrasi: App baru pakai SwiftUI lifecycle; sambungkan SDK lama via @UIApplicationDelegateAdaptor. App UIKit lama tetap valid memakai AppDelegate+SceneDelegate. Alasan perubahan: SwiftUI lifecycle menyatukan state transition ke satu sumber (scenePhase) yang deklaratif, lintas-platform (iOS/macOS/watchOS), dan mengurangi window-management boilerplate. SceneDelegate (iOS 13+) tetap relevan untuk multi-window UIKit.

04Bundle, Resources & Info.plist

Info.plist adalah manifest app: bundle ID, versi, capability, usage description permission. Resource diakses lewat Bundle.

// Membaca nilai Info.plist
let version = Bundle.main.infoDictionary?["CFBundleShortVersionString"] as? String

// Resource di app target
let url = Bundle.main.url(forResource: "config", withExtension: "json")

// Resource di dalam SPM package — WAJIB Bundle.module
let asset = Bundle.module.url(forResource: "seed", withExtension: "json")
Jebakan umumDi dalam SPM package, Bundle.main menunjuk ke app host, bukan package. Gunakan Bundle.module (di-generate otomatis saat target punya resources). Salah bundle = resource tidak ditemukan saat runtime.

05Permissions

Dua langkah wajib: (1) deklarasikan usage description string di Info.plist, (2) minta otorisasi lewat API framework. Tanpa string, app crash saat meminta izin.

IzinInfo.plist keyAPI request (modern)
KameraNSCameraUsageDescriptionAVCaptureDevice.requestAccess(for:) (async)
Notifikasi—UNUserNotificationCenter.requestAuthorization (async)
LokasiNSLocationWhenInUseUsageDescriptionCLLocationManager + delegate
FotoNSPhotoLibraryUsageDescriptionPHPhotoLibrary.requestAuthorization(for:)
Pola request async modern
import AVFoundation
import UserNotifications

func requestCamera() async -> Bool {
    await AVCaptureDevice.requestAccess(for: .video)
}

func requestNotifications() async throws -> Bool {
    try await UNUserNotificationCenter.current()
        .requestAuthorization(options: [.alert, .badge, .sound])
}
UX PrincipalMinta izin tepat saat fitur dibutuhkan (just-in-time), bukan saat launch. Sertakan pre-permission priming bila perlu (layar penjelasan sebelum dialog sistem), karena penolakan bersifat permanen sampai user mengubahnya di Settings. Selalu tangani status denied dengan jalur degradasi yang jelas.

06Latihan

EX 01

scenePhase handling

Tulis App yang menyimpan draft saat masuk background dan memuatnya kembali saat active.

▸ Lihat solusi & review 
@main struct DraftApp: App {
    @Environment(\.scenePhase) private var phase
    @State private var store = DraftStore()
    var body: some Scene {
        WindowGroup { EditorView(store: store) }
        .onChange(of: phase) { _, p in
            if p == .background { store.persist() }
            if p == .active { store.reload() }
        }
    }
}

Review: .background adalah titik aman terakhir untuk persist — sistem dapat menterminasi app kapan saja setelahnya. Jangan andalkan .inactive untuk simpan final.

EX 02

Multi-environment

Rancang strategi agar base URL berbeda antara Staging dan Production tanpa #if DEBUG tersebar. Sebutkan komponen Xcode yang dipakai.

▸ Lihat solusi & review

Buat build configuration Staging & Production → masing-masing .xcconfig berisi API_BASE_URL → ekspos ke Info.plist sebagai entri custom → baca via Bundle.main.infoDictionary. Tambahkan satu scheme per environment.

Review: Konfigurasi terpusat di .xcconfig membuat nilai environment auditable dan bebas dari logika tersebar. Ini juga yang dikonsumsi pipeline CI (Module 14).

EX 03

Permission flow

Implementasikan fungsi yang meminta izin kamera dan mengembalikan enum hasil: .granted, .denied, lalu jelaskan penanganan .denied.

▸ Lihat solusi & review 
enum CameraResult { case granted, denied }

func ensureCamera() async -> CameraResult {
    let ok = await AVCaptureDevice.requestAccess(for: .video)
    return ok ? .granted : .denied
}

Review: Saat .denied, jangan ulangi dialog (sistem tak akan menampilkannya lagi). Arahkan user ke UIApplication.openSettingsURLString dan sediakan fitur alternatif. Pastikan NSCameraUsageDescription ada di Info.plist atau app crash sebelum dialog muncul.

09Quiz, Mini-Project, Challenge & Referensi

Quiz Cepat

Jawab dulu di kepala, lalu buka jawaban.

Q1

App vs Scene lifecycle

Apa beda app lifecycle dan scene lifecycle, dan kenapa scene penting?

▸ Jawaban

App lifecycle mengatur proses aplikasi keseluruhan (launch, terminate). Scene lifecycle mengatur tiap UI scene (foreground/background) — penting untuk multi-window (iPad) dan mengelola state per-scene. SwiftUI App + WindowGroup mengabstraksi ini; SceneDelegate dipakai di UIKit lama.

Q2

Target vs scheme

Apa beda target dan scheme di Xcode?

▸ Jawaban

Target mendefinisikan satu produk build (app, extension, test bundle) dengan setting & file-nya. Scheme mendefinisikan bagaimana target di-build/run/test (konfigurasi, argumen, environment). Satu target bisa punya banyak scheme.

Q3

Info.plist

Kenapa string izin di Info.plist wajib, dan apa akibat bila absen?

▸ Jawaban

iOS mewajibkan usage description string untuk tiap izin sensitif; bila API izin dipanggil tanpa string yang sesuai, app crash. Ini kontrak privasi Apple — deklarasikan alasan pemakaian yang jujur (juga diperiksa App Review).

Mini-Project

Bangun: setup project produksiBuat project baru dengan struktur folder rapi (Features/, Core/, Resources/), dua scheme (Dev/Prod) dengan konfigurasi berbeda (base URL via xcconfig), dan Info.plist dengan minimal satu izin. Tujuan: menguasai anatomi project sebelum menulis fitur.

Challenge

Naik levelTambahkan build configuration ketiga (Staging) + xcconfig terpisah, dan wiring agar base URL/flag berubah otomatis per-scheme tanpa mengubah kode. Tantangan: pisahkan secret dari repo (jangan commit kunci) — fondasi menuju DevOps (M14).

Common Mistakes

  • Menaruh konfigurasi environment di dalam kode (hardcode URL) alih-alih xcconfig/scheme.
  • Mengabaikan string Info.plist hingga crash saat runtime.
  • Mencampur semua file dalam satu folder tanpa struktur — sulit skala.
  • Meng-commit kredensial/API key ke repo.
