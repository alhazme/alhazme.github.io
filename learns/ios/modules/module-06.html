MODULE 06 · PHASE 3 — UI DEVELOPMENTSwiftUI Deklaratif & Observation

SwiftUI mendeskripsikan UI sebagai fungsi dari state: UI = f(state). Anda tidak memanipulasi view; Anda mengubah state, dan framework merekonsiliasi tampilan. Module ini menguasai sistem state modern (Observation) yang menjadi tulang punggung itu.

iOS 27@ObservableNavigationStack~110 menit
Pergeseran besarSejak iOS 17, Observation framework (@Observable macro) menggantikan ObservableObject + @Published. Keuntungan: boilerplate hilang (semua stored property otomatis observable) dan re-render granular per-properti — view hanya rebuild saat properti yang benar-benar ia baca berubah. Ini sekaligus perbaikan performa dan kebenaran.

01View System

Sebuah View adalah struct ringan yang mendeklarasikan tampilan lewat body. View dikomposisi, bukan diwarisi. SwiftUI membuang & membangun ulang struct ini setiap render — murah karena value type.

struct OrderRow: View {
    let order: Order                      // input immutable
    var body: some View {
        HStack {
            VStack(alignment: .leading) {
                Text(order.id).font(.headline)
                Text(order.createdAt, style: .date)
                    .font(.caption).foregroundStyle(.secondary)
            }
            Spacer()
            Text(order.total, format: .currency(code: "IDR"))
        }
        .padding(.vertical, 4)
    }
}
Mental modelJangan simpan state turunan yang bisa dihitung — derive di body atau computed property. View adalah deskripsi, bukan tempat menyimpan. Memecah body raksasa menjadi sub-view kecil bukan sekadar kerapian: ia membatasi cakupan re-render.

02State: @State & @Observable

Dua sumber kebenaran berbeda peran:

@State@Observable class
TipeValue (struct/enum) atau model yang dimiliki viewReference (class)
CakupanLokal pada viewDibagikan lintas view
UntukToggle, teks input, state UIBusiness/model state
Old → New · Observable model
Old (pre-iOS 17) 
class CartVM: ObservableObject {
    @Published var items = [Item]()
}
struct CartView: View {
    @StateObject private var
        vm = CartVM()
}
New (Observation) 
@Observable
final class CartModel {
    var items = [Item]()   // auto-observable
}
struct CartView: View {
    @State private var
        cart = CartModel()
}
Migrasi: Ganti ObservableObject→@Observable, hapus semua @Published, ganti @StateObject→@State (untuk yang dimiliki view) dan @ObservedObject→property biasa. Alasan: properti kini dilacak otomatis dengan presisi bedah; view yang hanya membaca items.count tidak rebuild saat properti lain berubah. Boilerplate @Published hilang sepenuhnya.
@Observable dengan computed state
@Observable
final class CartModel {
    var items: [Item] = []
    var total: Decimal { items.reduce(0) { $0 + $1.price } }  // derived, bukan disimpan
    func add(_ item: Item) { items.append(item) }
}

03@Bindable & @Environment

Setelah model observable dibuat, dua cara menghubungkannya ke view lain:

@Bindable — binding dua arah ke properti observable
struct ProfileEditor: View {
    @Bindable var model: ProfileModel        // observable yang dimiliki view lain
    var body: some View {
        TextField("Nama", text: $model.name) // $ menghasilkan Binding
        Toggle("Notifikasi", isOn: $model.notificationsEnabled)
    }
}
@Environment — dependency injection lintas hierarki
// Inject di root
ContentView()
    .environment(authModel)          // satu instance dibagikan

// Baca di view mana pun di bawahnya
struct HeaderView: View {
    @Environment(AuthModel.self) private var auth
    var body: some View { Text(auth.currentUser?.name ?? "Tamu") }
}
Aturan pemilihan@State = view memiliki model (lifecycle). @Bindable = view menerima model & butuh binding edit. @Environment = dependency bersama yang dipakai banyak view jauh (auth, theme, router). Hindari menaruh semua di Environment — itu menyembunyikan dependency dan memperluas re-render.

04NavigationStack — Routing Type-Safe

NavigationStack dengan typed path memberi navigasi programatik, deep link, dan testability. Ia menggantikan NavigationView sepenuhnya.

Old → New · Navigation
Old — NavigationView 
NavigationView {
  List(orders) { o in
    NavigationLink(
      destination: Detail(o)) {
        OrderRow(order: o)
    }
  }
} // navigasi terikat view,
  // sulit deep link
New — NavigationStack 
NavigationStack(path: $path) {
  List(orders) { o in
    NavigationLink(value: o) {
      OrderRow(order: o)
    }
  }
  .navigationDestination(
    for: Order.self){ Detail($0) }
}
Migrasi: NavigationView→NavigationStack; NavigationLink(destination:)→NavigationLink(value:) + navigationDestination(for:). Alasan: path eksplisit & typed memungkinkan push/pop programatik, restore state, dan deep link (mis. buka order tertentu dari notifikasi) tanpa hack. Cocok untuk pola Router/Coordinator (lihat Module 07).
Router observable untuk navigasi programatik
@Observable final class Router {
    var path = NavigationPath()
    func push(_ value: any Hashable) { path.append(value) }
    func popToRoot() { path = NavigationPath() }
}

struct AppRoot: View {
    @State private var router = Router()
    var body: some View {
        @Bindable var router = router
        NavigationStack(path: $router.path) {
            HomeView()
                .navigationDestination(for: Order.self) { OrderDetail(order: $0) }
                .navigationDestination(for: Settings.self) { _ in SettingsView() }
        }
        .environment(router)
    }
}

05Animation

Animasi di SwiftUI bersifat deklaratif: Anda menganimasikan perubahan state, bukan memerintah frame.

struct ExpandCard: View {
    @State private var expanded = false
    var body: some View {
        VStack {
            Text("Detail").font(.headline)
            if expanded { Text("Konten tambahan").transition(.opacity.combined(with: .move(edge: .top))) }
            Button(expanded ? "Tutup" : "Buka") {
                withAnimation(.spring(response: 0.35, dampingFraction: 0.8)) {
                    expanded.toggle()          // animasikan perubahan state
                }
            }
        }
    }
}
Pilihan APIGunakan withAnimation { } untuk membungkus perubahan state eksplisit; gunakan .animation(_:value:) bila ingin terikat pada perubahan nilai tertentu. .transition mengatur insert/remove view. Hindari menganimasikan layout besar setiap frame — gunakan .drawingGroup() atau pisahkan subtree bila terjadi jank (Module 15).

06Custom Component & Design System

Konsistensi visual dicapai lewat design token + reusable component/modifier, bukan styling ad-hoc per view. Ini fondasi yang juga Anda jual sebagai Figma/Flutter UI kit.

Token + ButtonStyle + ViewModifier
enum AppColor { static let clay = Color(red: 0.85, green: 0.47, blue: 0.34) }
enum AppSpacing { static let md: CGFloat = 16 }

struct PrimaryButtonStyle: ButtonStyle {
    func makeBody(configuration: Configuration) -> some View {
        configuration.label
            .padding(.horizontal, AppSpacing.md).frame(height: 44)
            .background(AppColor.clay)
            .foregroundStyle(.white)
            .clipShape(RoundedRectangle(cornerRadius: 8))
            .opacity(configuration.isPressed ? 0.85 : 1)
    }
}

struct Card<Content: View>: View {
    @ViewBuilder var content: Content
    var body: some View {
        content.padding(AppSpacing.md)
            .background(.white, in: RoundedRectangle(cornerRadius: 12))
            .shadow(radius: 2, y: 1)
    }
}

// Pemakaian
Button("Bayar") { pay() }.buttonStyle(PrimaryButtonStyle())
Card { Text("Ringkasan pesanan") }
Prinsip PrincipalComponent generik (Card<Content>) + ButtonStyle/ViewModifier + token terpusat = design system yang berubah di satu tempat. Saat klien minta rebrand, Anda ubah token, bukan ratusan view. Ini juga yang membuat UI kit Anda layak dijual.

07Latihan

EX 01

Migrasi ke @Observable

Konversi view model ini ke Observation framework:

class SearchVM: ObservableObject {
    @Published var query = ""
    @Published var results: [Item] = []
}
▸ Lihat solusi & review 
@Observable final class SearchModel {
    var query = ""
    var results: [Item] = []
}
// di view: @State private var model = SearchModel()

Review: Hapus @Published dan conformance ObservableObject. View yang membaca results tidak akan rebuild saat hanya query berubah — re-render granular gratis.

EX 02

Binding ke observable

Buat editor untuk @Observable ProfileModel { var name; var bio } dengan dua TextField dua-arah.

▸ Lihat solusi & review 
struct ProfileEditor: View {
    @Bindable var model: ProfileModel
    var body: some View {
        Form {
            TextField("Nama", text: $model.name)
            TextField("Bio", text: $model.bio)
        }
    }
}

Review: @Bindable diperlukan agar $model.name menghasilkan Binding. Jika model hanya property biasa (read-only), $ tidak tersedia.

EX 03

Navigasi typed

Susun NavigationStack yang menampilkan list Order dan push ke OrderDetail saat dipilih, dengan path yang bisa di-reset programatik.

▸ Lihat solusi & review 
@State private var path = NavigationPath()
NavigationStack(path: $path) {
    List(orders) { o in NavigationLink(value: o) { OrderRow(order: o) } }
        .navigationDestination(for: Order.self) { OrderDetail(order: $0) }
}
// reset: path = NavigationPath()

Review: Order harus Hashable. Path eksplisit memungkinkan deep link & pop-to-root — fondasi Coordinator di Module 07.

EX 04

Reusable component

Buat StatusBadge yang menerima enum status dan menampilkan warna berbeda, memakai token terpusat.

▸ Lihat solusi & review 
enum Status { case paid, pending, failed }
struct StatusBadge: View {
    let status: Status
    private var color: Color {
        switch status { case .paid: .green; case .pending: .orange; case .failed: .red }
    }
    var body: some View {
        Text("\(status)").font(.caption).padding(.horizontal, 8).padding(.vertical, 3)
            .background(color.opacity(0.16), in: Capsule())
            .foregroundStyle(color)
    }
}

Review: Logika warna terpusat di satu computed property. Ganti palet = satu tempat. Komponen kecil & murni seperti ini ideal untuk Widgetbook/preview catalog.
