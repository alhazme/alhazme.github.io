MODULE 07 · PHASE 3 — UI DEVELOPMENTUIKit & Coordinator

SwiftUI adalah default untuk app baru, tetapi UIKit tetap relevan: codebase besar yang ada, kontrol granular (kamera, kustomisasi mendalam), dan beberapa API yang belum punya padanan SwiftUI. Principal engineer harus fasih keduanya dan tahu cara menjembataninya.

UIKitDiffable Data Source~100 menitInterop
Posisi 2026Strategi mayoritas tim: SwiftUI-first, UIKit where needed. Anda jarang membangun app UIKit penuh dari nol lagi, tetapi sering (a) memelihara layar UIKit lama, (b) membungkus komponen UIKit ke SwiftUI, atau (c) menempatkan layar SwiftUI di dalam navigasi UIKit. 01UIViewController Lifecycle

Berbeda dari SwiftUI yang deklaratif, UIViewController bersifat imperatif dengan callback lifecycle eksplisit. Menempatkan kerja di callback yang salah adalah sumber bug umum.

CallbackKapan dipanggilLetakkan
viewDidLoadSekali, setelah view dimuatSetup view hierarchy, binding (sekali)
viewWillAppearSetiap kali akan tampilRefresh data, update UI dinamis
viewDidAppearSetelah tampil penuhAnimasi mulai, analytics screen view
viewWillDisappearAkan menghilangSimpan state, hentikan timer
 
final class OrderListViewController: UIViewController {
    private let model: OrderListModel
    init(model: OrderListModel) { self.model = model; super.init(nibName: nil, bundle: nil) }
    required init?(coder: NSCoder) { fatalError("use init(model:)") }

    override func viewDidLoad() {
        super.viewDidLoad()
        view.backgroundColor = .systemBackground
        setupTableView()                 // sekali saja
    }
    override func viewWillAppear(_ animated: Bool) {
        super.viewWillAppear(animated)
        Task { await model.reload() }     // refresh tiap muncul
    }
}
JebakanMenaruh setup yang seharusnya sekali (membuat subview, constraint) di viewWillAppear menyebabkan duplikasi tiap layar muncul kembali. Sebaliknya, menaruh refresh data di viewDidLoad membuat data basi saat kembali dari layar lain.

02Auto Layout

Auto Layout mendefinisikan UI lewat constraint relasional. Di kode produksi, gunakan anchor API (programmatic) — lebih jelas dan reviewable daripada Storyboard untuk tim.

private func setupTableView() {
    let table = UITableView(frame: .zero, style: .insetGrouped)
    table.translatesAutoresizingMaskIntoConstraints = false   // WAJIB untuk Auto Layout
    view.addSubview(table)
    NSLayoutConstraint.activate([
        table.topAnchor.constraint(equalTo: view.safeAreaLayoutGuide.topAnchor),
        table.leadingAnchor.constraint(equalTo: view.leadingAnchor),
        table.trailingAnchor.constraint(equalTo: view.trailingAnchor),
        table.bottomAnchor.constraint(equalTo: view.bottomAnchor)
    ])
}
Tiga aturan wajib(1) Set translatesAutoresizingMaskIntoConstraints = false pada view yang Anda constrain manual. (2) Tambahkan view ke hierarchy sebelum mengaktifkan constraint. (3) Gunakan safeAreaLayoutGuide, bukan view langsung, untuk menghormati notch/Dynamic Island. Lupa salah satu = constraint conflict atau view tak terlihat.

03Diffable Data Source & Compositional Layout

Pendekatan modern untuk UITableView/UICollectionView. Menggantikan boilerplate dataSource/delegate klasik dan menghilangkan crash "inconsistent update".

Old → New · List data
Old — classic dataSource 
func tableView(_ t: UITableView,
  numberOfRowsInSection s: Int)
  -> Int { items.count }
func tableView(_ t: UITableView,
  cellForRowAt i: IndexPath)
  -> UITableViewCell { … }
// update manual → mudah
// crash bila state tak sinkron
New — diffable 
var snapshot = NSDiffableData
  SourceSnapshot
  <Section, Order>()
snapshot.appendSections([.main])
snapshot.appendItems(orders)
await dataSource.apply(
  snapshot, animatingDifferences: true)
Migrasi: Ganti delegate dataSource dengan UITableViewDiffableDataSource/UICollectionViewDiffableDataSource; perbarui UI dengan meng-apply snapshot. Alasan: diffable menghitung perbedaan secara otomatis & aman, memberi animasi gratis, dan menghapus seluruh kelas crash "number of rows inconsistent". Item harus Hashable. Compositional layout menggantikan flow layout untuk grid kompleks.
enum Section { case main }

private func makeDataSource(_ table: UITableView)
    -> UITableViewDiffableDataSource<Section, Order> {
    UITableViewDiffableDataSource(tableView: table) { table, indexPath, order in
        let cell = table.dequeueReusableCell(withIdentifier: "cell", for: indexPath)
        var config = cell.defaultContentConfiguration()
        config.text = order.id
        config.secondaryText = order.total.formatted(.currency(code: "IDR"))
        cell.contentConfiguration = config
        return cell
    }
}

04Coordinator Pattern

Masalah klasik UIKit: view controller saling tahu & melakukan navigasi sendiri (present/push), membuatnya terkopel dan sulit dipakai ulang. Coordinator mengekstrak logika navigasi keluar dari VC.

VC tidak tahu layar berikutnya. Ia melapor ke coordinator lewat delegate/closure.
protocol Coordinator: AnyObject {
    var navigationController: UINavigationController { get }
    func start()
}

final class AppCoordinator: Coordinator {
    let navigationController: UINavigationController
    init(_ nav: UINavigationController) { self.navigationController = nav }

    func start() { showOrderList() }

    private func showOrderList() {
        let vc = OrderListViewController(model: .init())
        vc.onSelect = { [weak self] order in self?.showDetail(order) }   // event keluar
        navigationController.pushViewController(vc, animated: false)
    }
    private func showDetail(_ order: Order) {
        let vc = OrderDetailViewController(order: order)
        navigationController.pushViewController(vc, animated: true)
    }
}
ManfaatVC menjadi reusable (tak terikat alur tertentu), navigasi terpusat & teruji, dan deep link mudah (coordinator membangun stack langsung). Padanan konsep ini di SwiftUI adalah Router + NavigationStack(path:) dari Module 06.

05SwiftUI ↔ UIKit Interop

Dua arah jembatan yang wajib dikuasai untuk migrasi bertahap:

UIKit di dalam SwiftUI — UIViewRepresentable
struct LegacyMapView: UIViewRepresentable {
    func makeUIView(context: Context) -> MKMapView { MKMapView() }
    func updateUIView(_ view: MKMapView, context: Context) { /* sync state → view */ }
}
// dipakai seperti View biasa: LegacyMapView().frame(height: 200)
SwiftUI di dalam UIKit — UIHostingController
let swiftUIScreen = ProfileView(model: profileModel)
let host = UIHostingController(rootView: swiftUIScreen)
navigationController.pushViewController(host, animated: true)
Strategi migrasiUntuk memodernkan app UIKit lama: bungkus layar baru sebagai SwiftUI lalu masukkan via UIHostingController ke navigasi UIKit yang ada. Migrasikan layar-per-layar, bukan rewrite besar sekaligus. State dijembatani lewat model @Observable yang dibagikan.

06Kapan SwiftUI, Kapan UIKit

SituasiPilihan
App/fitur baruSwiftUI — default
Codebase UIKit besar yang sudah adaUIKit, sisipkan SwiftUI bertahap
Kontrol kamera/render granular, API belum ada di SwiftUIUIKit, bungkus ke SwiftUI
Kustomisasi transisi/gesture sangat spesifikUIKit (atau SwiftUI + Representable)
Layar form, list, detail standarSwiftUI
Sikap PrincipalPertanyaannya bukan "SwiftUI atau UIKit" secara dogmatis, melainkan "interop mana yang menurunkan risiko & biaya". Default SwiftUI; turun ke UIKit hanya untuk kebutuhan konkret; selalu siapkan jembatan dua arah. Hindari menulis ulang aplikasi yang berfungsi hanya demi keseragaman teknologi.

07Latihan

EX 01

Tempatkan kerja di lifecycle

Anda perlu: (a) membangun table view; (b) memuat ulang data; (c) mencatat analytics "screen viewed". Letakkan masing-masing di callback yang tepat.

▸ Lihat solusi & review

(a) viewDidLoad — setup sekali. (b) viewWillAppear — segar tiap muncul. (c) viewDidAppear — setelah benar-benar tampil.

Review: Analytics di viewDidLoad akan melewatkan kunjungan ulang (VC tidak dimuat ulang). Reload di viewDidLoad membuat data basi saat kembali.

EX 02

Auto Layout penuh

Pin sebuah UILabel ke tengah view dengan margin horizontal 16pt, menghormati safe area atas.

▸ Lihat solusi & review 
label.translatesAutoresizingMaskIntoConstraints = false
view.addSubview(label)
NSLayoutConstraint.activate([
    label.centerYAnchor.constraint(equalTo: view.centerYAnchor),
    label.leadingAnchor.constraint(equalTo: view.leadingAnchor, constant: 16),
    label.trailingAnchor.constraint(equalTo: view.trailingAnchor, constant: -16)
])

Review: Trailing memakai konstanta negatif (arah berlawanan). Lupa translatesAutoresizing... = false adalah penyebab #1 constraint "tidak bekerja".

EX 03

Refactor ke Coordinator

LoginViewController saat ini memanggil present(HomeViewController()) sendiri. Ekstrak navigasi ke coordinator.

▸ Lihat solusi & review 
final class LoginViewController: UIViewController {
    var onLoginSuccess: (() -> Void)?       // event keluar, bukan navigasi langsung
}
// di coordinator:
loginVC.onLoginSuccess = { [weak self] in self?.showHome() }

Review: VC kini tidak tahu tujuan berikutnya — hanya melaporkan "login sukses". Coordinator yang memutuskan. VC jadi reusable & dapat diuji tanpa stack navigasi nyata.

EX 04

Interop

Anda punya layar SwiftUI SettingsView dan ingin menampilkannya dari navigasi UIKit. Tulis kodenya.

▸ Lihat solusi & review 
let host = UIHostingController(rootView: SettingsView(model: settingsModel))
navigationController.pushViewController(host, animated: true)

Review: UIHostingController membungkus View menjadi UIViewController. Inilah mekanisme inti migrasi bertahap dari UIKit ke SwiftUI tanpa rewrite.

09Quiz, Mini-Project, Challenge & Referensi

Quiz Cepat

Jawab dulu di kepala, lalu buka jawaban.

Q1

Kapan UIKit

Kapan masih memilih UIKit daripada SwiftUI di 2026?

▸ Jawaban

Saat butuh kontrol halus (kolaborasi text kompleks, kamera kustom, transisi/gesture rumit), integrasi library UIKit besar yang belum SwiftUI, atau maintenance codebase UIKit. Interop dua arah (UIViewControllerRepresentable / UIHostingController) memungkinkan campur keduanya.

Q2

Coordinator

Masalah apa yang dipecahkan Coordinator pattern?

▸ Jawaban

Memindahkan logika navigasi keluar dari view controller (yang seharusnya fokus UI), menjadikan flow navigasi terpusat, dapat diuji, dan view controller reusable. Menghindari VC yang saling tahu & tightly-coupled.

Q3

Auto Layout

Apa penyebab umum konflik/ambiguous layout?

▸ Jawaban

Constraint kurang (ambiguous) atau bertentangan (conflict); prioritas tak diset saat butuh fleksibilitas; content hugging/compression resistance salah. Debug via view hierarchy & log constraint.

Mini-Project

Bangun: flow dengan CoordinatorBangun flow login→home memakai Coordinator: AppCoordinator memegang navigasi, view controller hanya menampilkan UI & memanggil delegate/closure. Sisipkan satu layar SwiftUI via UIHostingController. Tujuan: menguasai navigasi terstruktur + interop.

Challenge

Naik levelTambahkan child coordinator (mis. onboarding) dengan lifecycle yang benar (start/finish, hindari retain cycle antar coordinator). Tantangan: kelola array child coordinator & pembersihan — pola nyata di app besar.

Common Mistakes

  • Menaruh logika navigasi di dalam view controller (VC saling coupling).
  • Retain cycle antar coordinator (parent↔child) tanpa weak reference.
  • Massive view controller — semua logika di satu VC.
  • Auto Layout ambiguous karena constraint kurang.
  • Memaksa UIKit untuk hal yang SwiftUI lebih sederhana.
