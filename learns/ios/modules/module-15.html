02Memory Optimization

Tiga sumber masalah memori paling umum di app iOS:

  • Retain cycle (M3) — objek saling strong, tak pernah deinit. Deteksi via Leaks + Memory Graph Debugger; perbaiki dengan [weak self].
  • Image memory — gambar full-resolution di memori. Downsample ke ukuran tampil (Kingfisher downsampling, M11) — sebuah foto 4000px yang ditampilkan 120px memboroskan ratusan kali memori.
  • Unbounded cache/collection — array/dictionary yang tumbuh tanpa batas. Gunakan NSCache (auto-evict saat memory pressure) atau batasi ukuran.
// Downsample sebelum menampilkan — hemat memori dramatis
func downsample(_ url: URL, to size: CGSize, scale: CGFloat) -> UIImage? {
    let opts = [kCGImageSourceShouldCache: false] as CFDictionary
    guard let src = CGImageSourceCreateWithURL(url as CFURL, opts) else { return nil }
    let maxDim = max(size.width, size.height) * scale
    let thumbOpts = [
        kCGImageSourceCreateThumbnailFromImageAlways: true,
        kCGImageSourceThumbnailMaxPixelSize: maxDim,
        kCGImageSourceCreateThumbnailWithTransform: true
    ] as CFDictionary
    guard let img = CGImageSourceCreateThumbnailAtIndex(src, 0, thumbOpts) else { return nil }
    return UIImage(cgImage: img)
}
Verifikasi deinitTambahkan deinit { print("X deinit") } saat mengembangkan; jika tak pernah tercetak saat layar ditutup, ada retain cycle. Konfirmasi dengan Memory Graph Debugger (ikon di debug bar) yang memvisualisasikan siapa me-retain siapa.

03Rendering & Hangs

UI mulus = 60/120 fps. "Hang" terjadi saat main thread diblokir > ~250ms — UI membeku. Penyebab tersering: kerja berat di main actor.

// SALAH — parsing berat memblokir UI (di MainActor default)
func load() async {
    let items = parseHugeJSON(data)   // blokir main thread → hang
    self.items = items
}

// BENAR — offload ke pool (M3), kembali ke main untuk update
@concurrent func parse(_ data: Data) async -> [Item] { parseHugeJSON(data) }

func load() async {
    let items = await Self.parse(data)   // paralel, tidak memblokir UI
    self.items = items                    // kembali ke main otomatis
}
Aturan main threadHanya update UI & kerja ringan di main actor. Kerja CPU-berat (parsing besar, image processing, kompresi, kripto) di-offload dengan @concurrent (M3). Untuk list, pastikan cell ringan & gambar di-downsample — ini penyebab #1 jank scroll. Gunakan lazy container (LazyVStack, List) untuk konten panjang.

05Security — OWASP MASVS

OWASP MASVS (Mobile Application Security Verification Standard) adalah kerangka standar keamanan mobile. Terapkan defense-in-depth di beberapa domain:

DomainPraktik
StorageToken/kredensial di Keychain (M5); jangan di UserDefaults/plist/log
NetworkHTTPS wajib (ATS); certificate pinning untuk endpoint sensitif
AuthEnforce di server; biometric gate untuk aksi sensitif
CodeJangan hardcode secret/API key di source; obfuscate bila perlu
PlatformDeteksi jailbreak untuk app berisiko tinggi (defense-in-depth, bukan absolut)
PrivacyMinimalkan data; PrivacyInfo manifest; screenshot protection untuk layar sensitif
 
// Biometric gate untuk aksi sensitif (mis. lihat saldo, transfer)
import LocalAuthentication

func authenticateBiometric() async throws -> Bool {
    let ctx = LAContext()
    var err: NSError?
    guard ctx.canEvaluatePolicy(.deviceOwnerAuthenticationWithBiometrics, error: &err) else {
        throw AuthError.biometricUnavailable
    }
    return try await ctx.evaluatePolicy(.deviceOwnerAuthenticationWithBiometrics,
        localizedReason: "Konfirmasi identitas untuk melanjutkan")
}
Prinsip intiKlien tidak pernah dipercaya sebagai otoritas keamanan. Jailbreak detection, obfuscation, dan pinning menaikkan biaya serangan (defense-in-depth) tetapi dapat di-bypass di device yang dikuasai penuh. Kontrol otoritatif (authorization, validasi) selalu di server. Client-side security memperlambat penyerang; server-side security menghentikannya.

06Certificate Pinning

Pinning memverifikasi bahwa server yang dihubungi memakai sertifikat/public key yang Anda harapkan — mencegah man-in-the-middle via CA palsu/proxy. Penting untuk endpoint auth & pembayaran.

// URLSession delegate — pin public key
final class PinningDelegate: NSObject, URLSessionDelegate {
    let pinnedKeyHashes: Set<String>   // hash SHA-256 public key yang dipercaya

    func urlSession(_ session: URLSession, didReceive challenge: URLAuthenticationChallenge,
        completionHandler: @escaping (URLSession.AuthChallengeDisposition, URLCredential?) -> Void) {
        guard let trust = challenge.protectionSpace.serverTrust,
              let hash = publicKeyHash(from: trust), pinnedKeyHashes.contains(hash) else {
            completionHandler(.cancelAuthenticationChallenge, nil)   // fail closed
            return
        }
        completionHandler(.useCredential, URLCredential(trust: trust))
    }
}
Trade-off pinningPin ke public key (bukan sertifikat penuh) agar tidak putus saat sertifikat di-renew dengan key yang sama. Sertakan backup pin untuk rotasi. Rencanakan update: jika key berubah tanpa app update, app lama akan gagal konek — pinning yang kaku bisa mematikan app di lapangan. Karena itu pinning umumnya hanya untuk endpoint paling sensitif, dengan strategi rotasi yang jelas. Alamofire/Moya menyediakan ServerTrustEvaluating yang menyederhanakan ini (M10).

07Latihan

EX 01

Diagnosa jank scroll

List gambar produk nge-lag saat scroll. Langkah diagnosa & perbaikan Anda?

▸ Lihat solusi & review

Profil dengan Time Profiler + Animation Hitches (Release, device). Kemungkinan: gambar full-res tidak di-downsample, cell terlalu berat, atau kerja di main thread. Perbaiki: downsample gambar (ukuran tampil), ringankan cell, offload pemrosesan dengan @concurrent, pakai lazy container.

Review: Measure-first: jangan menebak. Downsampling gambar adalah perbaikan jank #1 untuk list image-heavy.

EX 02

Retain cycle

Sebuah layar tidak pernah deinit setelah ditutup. Bagaimana mengonfirmasi & memperbaiki?

▸ Lihat solusi & review

Konfirmasi: tambahkan deinit log + Memory Graph Debugger untuk melihat retainer. Perbaiki: [weak self] pada closure yang disimpan, weak pada delegate/parent (M3).

Review: Retain cycle adalah kebocoran memori paling umum di iOS; Memory Graph Debugger memvisualisasikan siapa yang menahan.

EX 03

Threat model storage

App menyimpan: JWT, preferensi tema, riwayat transaksi cache. Di mana masing-masing, dan apa yang TIDAK boleh?

▸ Lihat solusi & review

JWT → Keychain (device-only). Tema → UserDefaults. Riwayat cache → SwiftData/Core Data (bisa dienkripsi bila sensitif). TIDAK boleh: JWT di UserDefaults/log; nomor kartu di mana pun (M12).

Review: Cocokkan sensitivitas data dengan mekanisme. Jangan pernah mencatat token/PII ke log (bocor via crash report/console).

EX 04

Pinning yang aman

Tim ingin pin sertifikat. Apa risiko & bagaimana menerapkannya agar tidak mematikan app saat renew?

▸ Lihat solusi & review

Risiko: renew sertifikat/key tanpa app update → app lama gagal konek. Mitigasi: pin ke public key (bukan cert), sertakan backup pin, punya strategi rotasi & remote config untuk mematikan pinning darurat. Terapkan hanya pada endpoint sensitif.

Review: Pinning menaikkan keamanan tapi menambah risiko operasional. Selalu rencanakan rotasi sebelum menerapkan.

09Quiz, Mini-Project, Challenge & Referensi

Quiz Cepat

Jawab dulu di kepala, lalu buka jawaban.

Q1

Instruments

Instrument mana untuk mendiagnosis: (a) memory leak, (b) jank scroll, (c) waktu launch?

▸ Jawaban

(a) Leaks/Allocations. (b) Time Profiler / Core Animation (hitches). (c) App Launch instrument. Ukur dulu sebelum optimasi — jangan menebak.

Q2

Certificate pinning

Apa yang dilindungi certificate pinning dan apa risikonya?

▸ Jawaban

Melindungi dari MITM dengan memvalidasi sertifikat server terhadap yang di-pin. Risiko: bila sertifikat berubah (rotasi) tanpa update app, koneksi putus — kelola rotasi & sediakan mekanisme update.

Q3

MASVS

Apa fokus utama OWASP MASVS?

▸ Jawaban

Standar verifikasi keamanan aplikasi mobile: penyimpanan data, kripto, autentikasi, komunikasi jaringan, interaksi platform, kualitas kode, dan resistensi reverse-engineering. Pakai sebagai checklist.

Mini-Project

Bangun: audit performa + keamanan miniAmbil fitur daftar+gambar, profil dengan Time Profiler & Allocations, terapkan downsampling gambar & caching, lalu tambahkan certificate pinning + simpan token di Keychain. Tujuan: siklus ukur→optimasi + baseline keamanan.

Challenge

Naik levelJalankan checklist MASVS ringkas pada app Anda, dokumentasikan temuan & mitigasi (ADR bila perlu). Tantangan: berpikir seperti penyerang (attack surface) — inti peran DevSecOps/QA principal.

Common Mistakes

  • Optimasi tanpa mengukur dulu (menebak bottleneck).
  • Menampilkan gambar full-res tanpa downsampling (memori membengkak).
  • Certificate pinning tanpa rencana rotasi (koneksi putus).
  • Menyimpan secret di UserDefaults/kode.
  • Menganggap keamanan hanya perimeter (bukan defense-in-depth).
