01Custom Property Wrapper

Property wrapper mengenkapsulasi logika akses sebuah properti (validasi, transformasi, penyimpanan) agar dapat dipakai ulang. Anda sudah memakai @State, @Observable — kini Anda membangun sendiri.

@UserDefault — persist ke UserDefaults secara deklaratif
@propertyWrapper
struct UserDefault<Value> {
    let key: String
    let defaultValue: Value
    var wrappedValue: Value {
        get { UserDefaults.standard.object(forKey: key) as? Value ?? defaultValue }
        set { UserDefaults.standard.set(newValue, forKey: key) }
    }
}

// Pemakaian — bersih & deklaratif
enum AppFlags {
    @UserDefault(key: "hasSeenOnboarding", defaultValue: false)
    static var hasSeenOnboarding: Bool
}
AppFlags.hasSeenOnboarding = true   // otomatis tersimpan
@Clamped — batasi nilai ke rentang
@propertyWrapper
struct Clamped<T: Comparable> {
    private var value: T
    private let range: ClosedRange<T>
    init(wrappedValue: T, _ range: ClosedRange<T>) {
        self.range = range
        self.value = min(max(wrappedValue, range.lowerBound), range.upperBound)
    }
    var wrappedValue: T {
        get { value }
        set { value = min(max(newValue, range.lowerBound), range.upperBound) }
    }
}

struct Player { @Clamped(0...100) var health: Int = 100 }
var p = Player(); p.health = 250; print(p.health)   // 100 — otomatis di-clamp
Anatomi wrapperWajib: wrappedValue (nilai yang diekspos). Opsional: init(wrappedValue:...) untuk parameter, dan projectedValue (bagian berikut). Compiler mengubah @Clamped(0...100) var health menjadi properti tersimpan bertipe Clamped<Int> + accessor yang memanggil wrappedValue.

02projectedValue — Nilai Kedua via $

projectedValue memberi "nilai tambahan" yang diakses dengan prefix $ — inilah mekanisme di balik $binding SwiftUI.

@propertyWrapper
struct Validated {
    private var value: String
    var wrappedValue: String { get { value } set { value = newValue } }
    var projectedValue: Bool { value.contains("@") }   // $email = valid?
    init(wrappedValue: String) { self.value = wrappedValue }
}

struct Form { @Validated var email: String = "" }
var f = Form(); f.email = "a@b.com"
print(f.$email)   // true — akses projectedValue lewat $
Untuk SwiftUIUntuk state yang reaktif di SwiftUI, gunakan @AppStorage (bawaan, reaktif) alih-alih @UserDefault custom — @UserDefault tidak memicu re-render View. Custom wrapper tepat untuk logika non-UI (validasi, clamping, transformasi) atau utilitas di luar View.

03Localization — String Catalog

Sejak Xcode 15, String Catalog (.xcstrings) menggantikan file .strings manual. Teks di UI otomatis terlokalisasi; plural & variasi dikelola visual di editor.

Old → New · Localization
Old — .strings + macro 
// Localizable.strings manual
"greeting" = "Halo";
// di kode:
Text(NSLocalizedString(
  "greeting", comment: ""))
New — String Catalog 
// .xcstrings dikelola di Xcode
Text("Halo")          // auto-localize
let s = String(
  localized: "Halo")  // di non-View
Migrasi: Tambahkan file String Catalog; Xcode mengekstrak string dari Text("...") & String(localized:) otomatis. Isi terjemahan per-bahasa di editor visual. Alasan: .xcstrings menyatukan ekstraksi, terjemahan, plural, dan status (butuh review/selesai) di satu tempat berbasis JSON yang version-control-friendly — menghapus sinkronisasi manual .strings yang rawan galat.
Plural & interpolasi
// String Catalog menangani plural per-bahasa secara otomatis:
Text("^[\(count) item](inflect: true)")   // "1 item" / "5 items"
Text("Halo, \(user.name)")                 // interpolasi aman
// Kunci untuk ID: locale id_ID punya aturan plural berbeda dari en
Praktik bilingual ID/ENJangan pernah menyusun kalimat dengan konkatenasi ("Anda punya " + count + " pesan") — urutan kata beda antar-bahasa. Gunakan string ber-placeholder utuh sebagai satu kunci. Sediakan bahasa dasar (development language) + terjemahan; set default via skema device.

04Locale-Aware Formatting

Angka, mata uang, dan tanggal berbeda format per-locale. Jangan format manual — pakai formatter locale-aware.

let amount = Decimal(1500000)
amount.formatted(.currency(code: "IDR"))                       // "Rp1.500.000" (id)
amount.formatted(.currency(code: "IDR").locale(Locale(identifier: "id_ID")))

let date = Date()
date.formatted(.dateTime.day().month().year().locale(Locale(identifier: "id_ID")))
Kasus produksi — Timezone WIB vs UTCServer umumnya menyimpan waktu dalam UTC; device pengguna di WIB (UTC+7). Bug klasik: parse tanggal UTC lalu tampilkan tanpa konversi → laporan transaksi bergeser 7 jam / salah hari. Aturan: simpan & kirim UTC (ISO 8601), konversi ke zona lokal hanya saat menampilkan memakai TimeZone.current. Untuk "transaksi hari ini", tentukan hari berdasarkan zona yang mana secara eksplisit (device atau server) — jangan ambigu.
Kasus produksi — IDR & DecimalRupiah bernilai besar tanpa sen; Double menimbulkan galat pembulatan pada agregasi (M5). Selalu Decimal untuk uang, dan format via .currency(code: "IDR") agar pemisah ribuan & simbol benar per-locale.

05Accessibility

Accessibility membuat app dapat dipakai lewat VoiceOver (pembaca layar), Dynamic Type (ukuran teks), dan teknologi bantu lain. Ini syarat App Store untuk banyak kategori, dan hal yang benar.

ModifierFungsi
.accessibilityLabelApa yang dibacakan VoiceOver (mis. ikon tanpa teks)
.accessibilityHintApa yang terjadi jika diaktifkan
.accessibilityValueNilai saat ini (mis. slider "70%")
.accessibilityAddTraitsPeran: .isButton, .isHeader, dll.
.accessibilityElement(children:)Gabung/pisah elemen anak
 
// Ikon-only button — WAJIB label, kalau tidak VoiceOver membaca "tombol" kosong
Button(action: addToCart) { Image(systemName: "cart.badge.plus") }
    .accessibilityLabel("Tambah ke keranjang")
    .accessibilityHint("Menambahkan produk ini ke keranjang belanja")

// Gabungkan kartu jadi satu elemen agar tidak dibaca terpisah-pisah
VStack { Text(product.name); Text(product.price) }
    .accessibilityElement(children: .combine)

// Dynamic Type — pakai font semantik, JANGAN ukuran tetap
Text("Judul").font(.headline)     // skala otomatis mengikuti setelan user
// Hindari: .font(.system(size: 14)) — tidak menskala
Uji dengan Accessibility InspectorJalankan Accessibility Inspector (Xcode → Open Developer Tool) dan nyalakan VoiceOver di device. Naikkan Dynamic Type ke ukuran terbesar — layout tidak boleh terpotong. Gunakan warna + ikon, bukan warna saja, untuk menyampaikan status (buta warna).

06Accessibility untuk Aplikasi ABK

Untuk vertikal Anda — anak dengan ASD, ADHD, disleksia — aksesibilitas adalah fitur inti, bukan pelengkap. Pertimbangan spesifik:

  • Reduce Motion — hormati @Environment(\.accessibilityReduceMotion); animasi berlebihan bisa memicu overstimulasi (ASD/ADHD).
  • Target sentuh besar — minimal 44×44pt; anak dengan kesulitan motorik butuh area tap lebih besar.
  • Dynamic Type + font ramah-disleksia — dukung teks besar; hindari font rapat/rumit.
  • Kontras tinggi & konsisten — hormati accessibilityReduceTransparency; visual jelas mengurangi beban kognitif.
  • Umpan balik multi-indera — visual + audio + haptic; jangan hanya satu kanal.
  • Kesederhanaan — kurangi elemen per layar; alur prediktabel (visual schedule).
@Environment(\.accessibilityReduceMotion) private var reduceMotion

withAnimation(reduceMotion ? nil : .spring) {   // matikan animasi bila diminta
    isExpanded.toggle()
}
Jembatan ke produk AndaPrinsip ini langsung memandu Canva ABK Template Kits & app ABK Anda: sensory-friendly, jadwal visual, target besar, umpan balik multi-indera. Aksesibilitas di sini bukan compliance — ia adalah value proposition produk.

07Latihan

EX 01

Property wrapper

Buat @Trimmed yang otomatis memangkas whitespace dari string yang di-set.

▸ Lihat solusi & review 
@propertyWrapper struct Trimmed {
    private var value = ""
    var wrappedValue: String {
        get { value }
        set { value = newValue.trimmingCharacters(in: .whitespacesAndNewlines) }
    }
    init(wrappedValue: String) { self.wrappedValue = wrappedValue }
}

Review: Transformasi terjadi di set. Pastikan init(wrappedValue:) juga melewati setter (memanggil self.wrappedValue =) agar nilai awal ikut di-trim.

EX 02

Localization aman

Perbaiki: Text("Anda punya " + String(count) + " pesan baru")

▸ Lihat solusi & review 
Text("^[\(count) pesan baru](inflect: true)")
// atau kunci ber-placeholder di String Catalog: "message_count"

Review: Konkatenasi mematahkan terjemahan (urutan kata & plural beda per-bahasa). Satu kunci utuh dengan placeholder memungkinkan penerjemah menyusun ulang kalimat.

EX 03

Accessibility ikon

Sebuah tombol favorit hanya ikon hati. Apa yang kurang untuk VoiceOver, dan bagaimana menyampaikan status aktif/nonaktif?

▸ Lihat solusi & review 
Button(action: toggle) { Image(systemName: isFav ? "heart.fill" : "heart") }
    .accessibilityLabel("Favorit")
    .accessibilityValue(isFav ? "Aktif" : "Nonaktif")
    .accessibilityAddTraits(.isButton)

Review: Ikon tanpa label dibaca kosong. accessibilityValue menyampaikan status tanpa mengandalkan warna/bentuk saja.

EX 04

Reduce Motion (ABK)

Layar reward anak punya animasi konfeti besar. Bagaimana menghormati anak yang sensitif terhadap gerakan?

▸ Lihat solusi & review

Baca @Environment(\.accessibilityReduceMotion); bila true, ganti konfeti dengan umpan balik statis (badge + suara lembut) alih-alih animasi penuh.

Review: Untuk ABK, menghormati Reduce Motion mencegah overstimulasi — ini keputusan desain inklusif, bukan sekadar toggle teknis.

08Quiz, Mini-Project, Challenge & Referensi

Quiz Cepat

Jawab dulu di kepala, lalu buka jawaban.

Q1

Property wrapper

Apa yang ditambahkan sebuah @propertyWrapper, dan kapan membuatnya sendiri?

▸ Jawaban

Property wrapper membungkus logika akses/penyimpanan properti (get/set + wrappedValue, opsional projectedValue via $). Buat sendiri untuk pola berulang lintas properti — mis. clamping nilai, UserDefaults-backed, atau trimming string. Jangan buat bila hanya dipakai sekali.

Q2

String Catalog

Kenapa String Catalog lebih baik daripada Localizable.strings manual?

▸ Jawaban

String Catalog (.xcstrings) mengelola terjemahan terpusat dengan status per-string, pluralization, dan ekstraksi otomatis dari kode — mengurangi kesalahan sinkronisasi. Menggantikan pengelolaan .strings manual yang rawan drift.

Q3

Aksesibilitas ABK

Sebutkan tiga pertimbangan aksesibilitas penting untuk pengguna ABK.

▸ Jawaban

Reduce Motion (kurangi animasi bagi sensitivitas vestibular), target sentuh besar & jelas (motorik halus), dan umpan balik multi-indera (visual+audio+haptic). Plus Dynamic Type & label VoiceOver bermakna. Aksesibilitas adalah desain inti, bukan tambahan.

Mini-Project

Bangun: format lokal + wrapperBuat @propertyWrapper untuk trimming/validasi string, terapkan pada model form. Tambahkan format IDR (Decimal + currency) dan tanggal WIB (FormatStyle), serta pindahkan semua string UI ke String Catalog. Tujuan: lokalisasi benar + property wrapper reusable.

Challenge

Naik levelAudit satu layar untuk aksesibilitas: Dynamic Type (layout tak putus di ukuran besar), VoiceOver (label & urutan bermakna), Reduce Motion, dan target sentuh. Tantangan: rancang untuk ABK sejak awal — target besar, multi-indera, minim distraksi.

Common Mistakes

  • Membuat property wrapper untuk hal yang hanya dipakai sekali (over-engineering).
  • Hardcode string UI alih-alih String Catalog.
  • Format uang dengan Double / string manual, bukan Decimal + FormatStyle.
  • Mengabaikan Dynamic Type (layout putus di ukuran besar).
  • Menganggap aksesibilitas fitur tambahan, bukan desain inti.
