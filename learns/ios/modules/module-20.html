01WidgetKit

Widget adalah view SwiftUI yang di-render sistem pada interval yang Anda tentukan lewat timeline. Widget tidak "hidup" terus — sistem meminta snapshot & timeline, lalu me-render sendiri.

import WidgetKit
import SwiftUI

// 1. Entry — satu titik waktu data
struct OrderEntry: TimelineEntry {
    let date: Date
    let activeOrders: Int
    let nextDelivery: String
}

// 2. Provider — memasok timeline
struct OrderProvider: TimelineProvider {
    func placeholder(in context: Context) -> OrderEntry {
        OrderEntry(date: .now, activeOrders: 0, nextDelivery: "—")
    }
    func getSnapshot(in context: Context, completion: @escaping (OrderEntry) -> Void) {
        completion(loadEntry())          // untuk preview cepat
    }
    func getTimeline(in context: Context, completion: @escaping (Timeline<OrderEntry>) -> Void) {
        let entry = loadEntry()          // baca dari App Group
        // refresh lagi ~30 menit; sistem yang memutuskan waktu persisnya
        let next = Calendar.current.date(byAdding: .minute, value: 30, to: .now)!
        completion(Timeline(entries: [entry], policy: .after(next)))
    }
    private func loadEntry() -> OrderEntry {
        // Fail closed: App Group bisa salah konfigurasi — jangan force-unwrap.
        guard let d = UserDefaults(suiteName: "group.com.alhazme.app") else {
            return OrderEntry(date: .now, activeOrders: 0, nextDelivery: "—")
        }
        return OrderEntry(date: .now,
            activeOrders: d.integer(forKey: "activeOrders"),
            nextDelivery: d.string(forKey: "nextDelivery") ?? "—")
    }
}

// 3. View — SwiftUI, subset terbatas
struct OrderWidgetView: View {
    let entry: OrderEntry
    var body: some View {
        VStack(alignment: .leading, spacing: 6) {
            Text("\(entry.activeOrders) pesanan aktif").font(.headline)
            Text("Kirim berikutnya: \(entry.nextDelivery)").font(.caption)
        }
        .containerBackground(.fill.tertiary, for: .widget)   // wajib iOS 17+
    }
}

// 4. Widget declaration
struct OrderWidget: Widget {
    var body: some WidgetConfiguration {
        StaticConfiguration(kind: "OrderWidget", provider: OrderProvider()) { entry in
            OrderWidgetView(entry: entry)
        }
        .configurationDisplayName("Status Pesanan")
        .supportedFamilies([.systemSmall, .systemMedium, .accessoryRectangular])
    }
}
Batas & disiplinSistem membatasi frekuensi refresh widget (hemat baterai) — jangan andalkan widget untuk data real-time (itu tugas Live Activity). Widget diperbarui dari App Group; app utama menulis data, panggil WidgetCenter.shared.reloadTimelines(ofKind:) saat data berubah. View widget hanya subset SwiftUI (tanpa scroll/interaksi bebas — kecuali Button/Toggle via App Intents, bagian 03).

02App Intents

App Intents mengekspos aksi app ke Siri, Shortcuts, Spotlight, dan widget interaktif. Ganti SiriKit lama untuk mayoritas kasus.

Definisi intent — satu aksi yang dapat dipanggil sistem
import AppIntents

struct ReorderIntent: AppIntent {
    static var title: LocalizedStringResource = "Pesan Ulang"
    static var description = IntentDescription("Membuat ulang pesanan terakhir Anda.")

    @Parameter(title: "Produk")
    var product: ProductEntity

    func perform() async throws -> some IntentResult & ProvidesDialog {
        try await OrderService.shared.reorder(product.id)
        return .result(dialog: "Pesanan \(product.name) dibuat.")
    }
}

// Ekspos ke Shortcuts otomatis
struct AppShortcuts: AppShortcutsProvider {
    static var appShortcuts: [AppShortcut] {
        AppShortcut(intent: ReorderIntent(),
            phrases: ["Pesan ulang di \(.applicationName)"],
            shortTitle: "Pesan Ulang", systemImageName: "cart")
    }
}
AppEntity & konsistensiTipe domain yang dipakai intent (mis. ProductEntity) mengadopsi AppEntity + punya EntityQuery agar sistem bisa mencari/menyarankannya. Karena logika bisnis ada di use case (M8), perform() cukup memanggil use case yang sama dengan yang dipakai UI — satu sumber logika, banyak permukaan (UI, Siri, Shortcuts, widget).

03Interactive Widget (Button/Toggle)

Sejak iOS 17, widget bisa punya Button/Toggle yang menjalankan App Intent langsung tanpa membuka app.

struct ToggleTaskIntent: AppIntent {
    static var title: LocalizedStringResource = "Tandai Selesai"
    @Parameter(title: "Task ID") var taskID: String
    func perform() async throws -> some IntentResult {
        await TaskStore.shared.complete(taskID)      // tulis ke App Group
        return .result()
    }
}

// Di dalam view widget — tombol langsung
Button(intent: ToggleTaskIntent(taskID: task.id)) {
    Image(systemName: task.done ? "checkmark.circle.fill" : "circle")
}
Kasus vertikal — jadwal ABKWidget jadwal harian anak (ABK) dengan tombol centang per aktivitas: anak/orang tua menandai selesai langsung dari home screen tanpa membuka app. ToggleTaskIntent menulis ke App Group, lalu WidgetCenter.shared.reloadTimelines memperbarui tampilan. Sederhana, minim friksi — selaras prinsip aksesibilitas M17.

04ActivityKit — Live Activity

Live Activity menampilkan status real-time di Lock Screen & Dynamic Island — sempurna untuk tracking pesanan/pengiriman (vertikal logistik Anda).

import ActivityKit

// 1. Attributes — data statis + dynamic state
struct DeliveryAttributes: ActivityAttributes {
    public struct ContentState: Codable, Hashable {
        var status: String        // "Dikemas" → "Dikirim" → "Tiba"
        var etaMinutes: Int
    }
    var orderID: String           // statis selama activity
}

// 2. Mulai activity (dari app utama)
func startDelivery(orderID: String) throws {
    let attributes = DeliveryAttributes(orderID: orderID)
    let state = DeliveryAttributes.ContentState(status: "Dikemas", etaMinutes: 30)
    _ = try Activity.request(
        attributes: attributes,
        content: .init(state: state, staleDate: nil),
        pushType: .token)         // update via push (APNs)
}

// 3. Update (dari server via push, atau lokal)
func update(_ activity: Activity<DeliveryAttributes>, status: String, eta: Int) async {
    await activity.update(.init(state: .init(status: status, etaMinutes: eta), staleDate: nil))
}
func end(_ activity: Activity<DeliveryAttributes>) async {
    await activity.end(nil, dismissalPolicy: .default)
}
Update via pushLive Activity paling kuat di-update dari server via APNs (pushType: .token) — server kirim update status pengiriman, Lock Screen berubah tanpa app dibuka. UI-nya deklarasikan di widget extension yang sama (varian Dynamic Island: compact/minimal/expanded). Wajib entitlement NSSupportsLiveActivities = YES di Info.plist. Ada batas durasi (activity tidak boleh berjalan tak terbatas). Verifikasi batas & kebijakan terkini karena berubah antar versi iOS.

05PassKit — Apple Wallet

PassKit menambahkan pass (kartu loyalty, tiket, kupon, boarding pass) ke Apple Wallet — relevan langsung untuk membership/hospitality Anda.

Arsitektur pass — sisi serverFile .pkpass harus ditandatangani dengan sertifikat Pass Type ID Anda — ini dilakukan di server (butuh private key; jangan di klien). Struktur: pass.json (field, warna, barcode) + gambar (logo/icon) + manifest + signature, di-zip menjadi .pkpass. Klien hanya mengunduh & mempresentasikannya.

import PassKit

// Klien: tambahkan pass yang sudah ditandatangani server ke Wallet
func addToWallet(passData: Data, from presenter: UIViewController) throws {
    let pass = try PKPass(data: passData)                  // .pkpass dari server
    guard let addVC = PKAddPassesViewController(pass: pass) else { return }
    // present dari view controller pemanggil (mis. self di UIKit,
    // atau via UIViewControllerRepresentable/koordinator di SwiftUI).
    // Catatan: `topViewController` BUKAN API bawaan — jangan diasumsikan ada.
    presenter.present(addVC, animated: true)
}

// Cek apakah pass sudah ada di library
let library = PKPassLibrary()
let alreadyAdded = library.containsPass(pass)
Kasus vertikal — kartu loyalty hospitalityKartu membership JHL/hotel di Apple Wallet: server generate .pkpass bertanda tangan dengan barcode member + saldo poin. Push update memungkinkan saldo/tier di kartu berubah otomatis (mis. setelah transaksi) via web service pass. Update dinamis inilah nilai utama dibanding kartu statis.

06CarPlay

CarPlay memproyeksikan UI app ke dasbor mobil. Sangat terbatas & ter-template demi keselamatan — hanya kategori tertentu yang diizinkan (navigasi, audio, komunikasi, EV charging, driving task, parking, quick food ordering).

import CarPlay

// Scene delegate khusus CarPlay — UI via template, BUKAN SwiftUI/UIKit bebas
class CarPlaySceneDelegate: UIResponder, CPTemplateApplicationSceneDelegate {
    func templateApplicationScene(_ scene: CPTemplateApplicationScene,
        didConnect interfaceController: CPInterfaceController) {
        let items = [CPListItem(text: "Order #1024", detailText: "Antar ke Kemang")]
        let section = CPListSection(items: items)
        let list = CPListTemplate(title: "Pengiriman", sections: [section])
        interfaceController.setRootTemplate(list, animated: true, completion: nil)
    }
}
Batas keras CarPlay(1) Butuh entitlement khusus dari Apple (request terpisah, tidak otomatis) sesuai kategori app. (2) UI hanya template sistem (CPListTemplate, CPGridTemplate, CPMapTemplate, dll.) — bukan view bebas, demi keselamatan mengemudi. (3) Relevan untuk vertikal Anda hanya bila ada driver/logistics app. Untuk mayoritas app e-commerce/hospitality, CarPlay tidak berlaku. Ketersediaan kategori berubah; verifikasi ke dokumentasi Apple terkini sebelum berkomitmen.

07Latihan

EX 01

Data widget ↔ app

Widget Anda menampilkan jumlah pesanan aktif tetapi tidak pernah update setelah app mengubah data. Apa yang kurang?

▸ Lihat solusi & review

(1) App & widget harus berbagi App Group (UserDefaults(suiteName:) atau shared container). (2) App menulis data ke sana. (3) Panggil WidgetCenter.shared.reloadTimelines(ofKind:) saat data berubah agar sistem me-render ulang.

Review: Extension proses terpisah — tanpa App Group, widget tak melihat data app. reload memicu refresh di luar jadwal timeline biasa.

EX 02

Satu logika banyak permukaan

Aksi "Pesan Ulang" harus tersedia di UI, Siri, dan widget. Bagaimana menghindari duplikasi logika?

▸ Lihat solusi & review

Letakkan logika di use case (M8). UI button, ReorderIntent.perform(), dan tombol widget semuanya memanggil use case yang sama. Intent hanya adaptor tipis ke logika domain.

Review: "Build once, scale many" — App Intents menjadi permukaan tambahan di atas domain yang sama, bukan implementasi paralel.

EX 03

Widget vs Live Activity

Anda ingin menampilkan status pengiriman yang berubah tiap beberapa menit. Widget atau Live Activity?

▸ Lihat solusi & review

Live Activity (ActivityKit) — dirancang untuk status real-time berdurasi terbatas, di-update via push, tampil di Lock Screen/Dynamic Island. Widget dibatasi frekuensi refresh-nya dan tidak untuk real-time.

Review: Widget = info sekilas yang jarang berubah; Live Activity = status berlangsung yang aktif berubah. Pilih sesuai sifat data.

EX 04

Menandatangani pass

Seorang engineer ingin generate & tandatangani .pkpass di dalam app iOS. Kenapa ini keliru?

▸ Lihat solusi & review

Penandatanganan butuh private key Pass Type ID — menaruh private key di klien = kebocoran kredensial (M15). Pass harus di-generate & ditandatangani di server; klien hanya mengunduh .pkpass jadi dan mempresentasikannya via PKAddPassesViewController.

Review: Prinsip "klien tak dipercaya" berlaku: rahasia penandatanganan tidak pernah di device.

08Quiz, Mini-Project, Challenge & Referensi

Quiz Cepat

Jawab dulu di kepala, lalu buka jawaban.

Q1

App Group

Kenapa widget/extension butuh App Group untuk berbagi data dengan app?

▸ Jawaban

Extension berjalan di proses terpisah — tak berbagi memori. App Group menyediakan shared container (UserDefaults suite / file / SwiftData groupContainer) sebagai jembatan data antara app & extension.

Q2

Widget vs Live Activity

Kapan Widget, kapan Live Activity?

▸ Jawaban

Widget: info sekilas yang jarang berubah (refresh di-throttle sistem). Live Activity: status real-time berdurasi terbatas di Lock Screen/Dynamic Island, di-update via push. Pilih sesuai sifat data.

Q3

PassKit signing

Kenapa .pkpass ditandatangani di server, bukan klien?

▸ Jawaban

Penandatanganan butuh private key Pass Type ID; menaruh private key di klien = kebocoran kredensial. Server generate & tandatangani; klien hanya mengunduh & mempresentasikan.

Mini-Project

Bangun: widget + intentBuat widget yang membaca data dari App Group (mis. jumlah pesanan) dengan TimelineProvider, dan satu App Intent (aksi 'pesan ulang') yang memanggil use case yang sama dengan UI. Tujuan: extension + build-once logic.

Challenge

Naik levelTambahkan Live Activity tracking pengiriman (di-update via push) dan widget interaktif (Button/Toggle intent) yang menulis ke App Group lalu reloadTimelines. Tantangan: satu logika domain melayani UI + Siri + widget.

Common Mistakes

  • Extension mengasumsikan akses memori app (bukan App Group).
  • Widget untuk data real-time (harusnya Live Activity).
  • App Intent menduplikasi logika bisnis alih-alih memanggil use case.
  • Menandatangani .pkpass di klien (kebocoran private key).
  • Lupa reloadTimelines setelah data App Group berubah.
