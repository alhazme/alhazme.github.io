01CloudKit

Sinkronisasi data ke iCloud milik user — tanpa server sendiri. Tiga database: private (data user, di kuota iCloud mereka), public (dibagikan semua user), shared (dibagikan antar user tertentu).

import CloudKit

let container = CKContainer.default()
let db = container.privateCloudDatabase

// Simpan record
func save(_ template: ABKTemplate) async throws {
    let record = CKRecord(recordType: "ABKTemplate")
    record["title"] = template.title as CKRecordValue
    record["json"]  = template.jsonData as CKRecordValue
    _ = try await db.save(record)
}

// Query
func fetchTemplates() async throws -> [CKRecord] {
    let query = CKQuery(recordType: "ABKTemplate", predicate: NSPredicate(value: true))
    let (results, _) = try await db.records(matching: query)
    return results.compactMap { try? $0.1.get() }
}
SwiftData + CloudKit (jalur termudah)Untuk app SwiftUI, cara paling ringkas adalah SwiftData dengan sync CloudKit otomatis — set ModelConfiguration(cloudKitDatabase: .automatic) (M5/M18). Anda menulis SwiftData biasa, sync ke private DB berjalan otomatis. Gunakan CloudKit API langsung hanya bila butuh public/shared DB atau kontrol granular.
Kasus produksi — konflik & akun iCloud(1) User bisa tidak login iCloud — cek accountStatus() dulu; degradasi ke lokal bila tak tersedia. (2) Sync bersifat eventual — jangan asumsikan data langsung ada di device lain. (3) Konflik ditangani dengan CKRecord recordChangeTag/server-record — mirip strategi offline M12. Untuk ABK templates yang dipakai lintas device orang tua/terapis, uji skenario tanpa iCloud & sync tertunda.

02MapKit

Peta native dengan anotasi, overlay, rute, dan geocoding. Di SwiftUI, Map kini deklaratif.

import MapKit
import SwiftUI

struct StoreMap: View {
    @State private var camera: MapCameraPosition = .automatic
    let stores: [Store]
    var body: some View {
        Map(position: $camera) {
            ForEach(stores) { store in
                Marker(store.name, coordinate: store.coordinate)   // anotasi
            }
            UserAnnotation()                                       // posisi user (butuh izin lokasi M19)
        }
        .mapControls { MapUserLocationButton(); MapCompass() }
    }
}

// Geocoding: alamat → koordinat
func geocode(_ address: String) async throws -> CLLocationCoordinate2D? {
    let placemarks = try await CLGeocoder().geocodeAddressString(address)
    return placemarks.first?.location?.coordinate
}
Rute & batas kuotaUntuk rute/ETA gunakan MKDirections (MKDirections.Request dengan source/destination). Geocoding & directions punya rate limit sistem — jangan panggil per-keystroke; debounce (Combine, M11) & cache hasil. UserAnnotation menuntut izin lokasi (M19); tangani penolakan (tampilkan peta tanpa titik user).
Kasus vertikal — logistik & lokasi tokoPeta multi-toko + rute pengiriman: plot semua mini-warehouse (relevan Weemes Anda), hitung rute dengan MKDirections, tampilkan ETA. Untuk banyak titik, kelompokkan anotasi (clustering via MKClusterAnnotation di MapKit UIKit) agar peta tak penuh.

03Core Image

Pemrosesan gambar GPU-accelerated: filter, koreksi, deteksi. Pipeline: CIImage → CIFilter → render via CIContext.

import CoreImage
import CoreImage.CIFilterBuiltins

func enhance(_ input: UIImage) -> UIImage? {
    guard let ci = CIImage(image: input) else { return nil }
    let filter = CIFilter.colorControls()
    filter.inputImage = ci
    filter.saturation = 1.1
    filter.contrast = 1.05
    guard let output = filter.outputImage else { return nil }

    let context = CIContext()        // mahal — buat SEKALI, reuse
    guard let cg = context.createCGImage(output, from: output.extent) else { return nil }
    return UIImage(cgImage: cg)
}
Performa (sambung M15)CIContext mahal dibuat — instansiasi sekali & pakai ulang, jangan per-gambar. Pemrosesan berat jangan di main thread — offload dengan @concurrent (M3). Untuk thumbnail, downsample dulu (M15) sebelum filter agar hemat memori. Core Image juga punya deteksi (wajah, barcode via CIDetector), tapi untuk scan barcode real-time, Vision/AVFoundation metadata lebih tepat.

04Core Audio / AVAudioEngine

Untuk mayoritas kasus (rekam, putar, mixing), AVAudioEngine (high-level) cukup — Core Audio mentah hanya untuk latensi sangat rendah / DSP kustom.

import AVFoundation

final class AudioRecorder {
    private let engine = AVAudioEngine()

    func startRecording(to url: URL) throws {
        let session = AVAudioSession.sharedInstance()
        try session.setCategory(.record, mode: .default)
        try session.setActive(true)                        // butuh izin mikrofon (M19)

        let input = engine.inputNode
        let format = input.outputFormat(forBus: 0)
        // Init AVAudioFile untuk menulis; verifikasi label parameter terhadap
        // SDK terkini (signature commonFormat/interleaved bisa berubah antar versi).
        let file = try AVAudioFile(forWriting: url, settings: format.settings,
                                   commonFormat: .pcmFormatFloat32, interleaved: false)

        input.installTap(onBus: 0, bufferSize: 1024, format: format) { buffer, _ in
            try? file.write(from: buffer)
        }
        try engine.start()
    }
    func stop() { engine.inputNode.removeTap(onBus: 0); engine.stop() }
}
AVAudioSession — inti yang sering terlupakanKonfigurasi AVAudioSession (category/mode) menentukan perilaku: apakah audio ter-mix dengan app lain, main saat silent switch, atau lanjut di background. Salah kategori = audio tak keluar atau app lain terputus. Untuk pemutaran sederhana, AVAudioPlayer lebih ringkas dari engine. Rekam butuh izin mikrofon (M19).

05Core Motion

Akses sensor gerak: accelerometer, gyroscope, pedometer, dan klasifikasi aktivitas.

import CoreMotion

final class MotionService {
    private let pedometer = CMPedometer()

    func todaySteps() async throws -> Int {
        guard CMPedometer.isStepCountingAvailable() else { return 0 }
        let start = Calendar.current.startOfDay(for: .now)
        return try await withCheckedThrowingContinuation { cont in
            pedometer.queryPedometerData(from: start, to: .now) { data, err in
                if let err { cont.resume(throwing: err) }
                else { cont.resume(returning: data?.numberOfSteps.intValue ?? 0) }
            }
        }
    }
}
Ketersediaan & izinSelalu cek isStepCountingAvailable() / isActivityAvailable() — tidak semua device punya co-processor gerak. Pedometer/motion butuh NSMotionUsageDescription. Untuk data historis, pedometer bisa query mundur beberapa hari (disimpan sistem). Streaming realtime (accelerometer) menguras baтерai — hentikan saat tak dipakai (M15).

06Core Bluetooth

Komunikasi Bluetooth Low Energy. App biasanya berperan central (memindai & connect ke peripheral seperti sensor/perangkat IoT).

import CoreBluetooth

final class BLEScanner: NSObject, CBCentralManagerDelegate {
    private var central: CBCentralManager!
    override init() { super.init(); central = CBCentralManager(delegate: self, queue: nil) }

    func centralManagerDidUpdateState(_ central: CBCentralManager) {
        guard central.state == .poweredOn else { return }        // cek state dulu
        central.scanForPeripherals(withServices: [myServiceUUID]) // filter by service
    }
    func centralManager(_ c: CBCentralManager, didDiscover p: CBPeripheral,
        advertisementData: [String: Any], rssi RSSI: NSNumber) {
        c.stopScan(); c.connect(p)                                // connect lalu discover services/characteristics
    }
}
Delegate-heavy & izinCore Bluetooth sangat berbasis delegate: state → scan → discover → connect → discover services → characteristics → read/notify. Butuh NSBluetoothAlwaysUsageDescription. Selalu tangani centralManagerDidUpdateState (jangan scan sebelum .poweredOn). Bungkus rantai delegate ini di balik service class dengan API async/closure yang bersih agar tak bocor ke UI. BLE menguras baterai — batasi durasi scan.

07HealthKit

Baca/tulis data kesehatan dari Health app. Izin bersifat granular per tipe data (langkah, detak jantung, dll.) dan terpisah baca vs tulis.

import HealthKit

let store = HKHealthStore()

func requestAuth() async throws {
    guard HKHealthStore.isHealthDataAvailable() else { return }   // iPad umumnya tak ada
    let steps = HKQuantityType(.stepCount)
    try await store.requestAuthorization(toShare: [steps], read: [steps])
}
Privasi HealthKit — aturan ketat(1) Butuh HealthKit entitlement + dua string Info.plist: NSHealthShareUsageDescription (baca) & NSHealthUpdateUsageDescription (tulis). (2) Anda tak bisa tahu apakah user menolak baca — demi privasi, query hanya mengembalikan kosong; jangan asumsikan "kosong = tidak ada data". (3) Data kesehatan tak boleh dipakai untuk iklan/dijual — pelanggaran = penolakan App Review keras. (4) isHealthDataAvailable() wajib dicek.

08HomeKit

Kontrol aksesori rumah pintar (lampu, kunci, termostat) via HMHomeManager. Relevan untuk skenario hospitality (kontrol kamar) atau smart home.

import HomeKit

final class HomeController: NSObject, HMHomeManagerDelegate {
    private let manager = HMHomeManager()
    override init() { super.init(); manager.delegate = self }

    func homeManagerDidUpdateHomes(_ mgr: HMHomeManager) {
        guard let home = mgr.primaryHome else { return }
        // akses accessories → services → characteristics untuk kontrol
    }
}
Entitlement & nicheButuh HomeKit entitlement + NSHomeKitUsageDescription. Model: Home → Room → Accessory → Service → Characteristic. Untuk vertikal Anda, HomeKit hanya relevan pada kasus spesifik (mis. app hospitality yang mengontrol perangkat kamar) — untuk mayoritas proyek, ini tak berlaku. Testing butuh aksesori nyata atau HomeKit Accessory Simulator. Verifikasi kebutuhan sebelum berkomitmen — ini area niche.

09CryptoKit

Kriptografi modern & aman: hashing, symmetric/asymmetric encryption, signing — API tinggi yang sulit disalahgunakan. Relevan langsung untuk keamanan fintech Anda.

import CryptoKit

// Hashing (mis. integritas / fingerprint)
let digest = SHA256.hash(data: Data("payload".utf8))
let hex = digest.map { String(format: "%02x", $0) }.joined()

// Symmetric encryption (AES-GCM)
let key = SymmetricKey(size: .bits256)                     // simpan key di Keychain (M5)!
let sealed = try AES.GCM.seal(Data("rahasia".utf8), using: key)
guard let ciphertext = sealed.combined else { throw CryptoError.sealFailed }  // .combined optional
let decrypted = try AES.GCM.open(AES.GCM.SealedBox(combined: ciphertext), using: key)

// Signing (Ed25519 / P256)
let signingKey = Curve25519.Signing.PrivateKey()
let signature = try signingKey.signature(for: Data("data".utf8))
let valid = signingKey.publicKey.isValidSignature(signature, for: Data("data".utf8))
Aturan kriptografi (sambung M15)(1) Kunci hidup di Keychain / Secure Enclave, tak pernah hardcode atau di UserDefaults. Untuk perlindungan hardware, pakai SecureEnclave.P256 — private key tak pernah keluar dari chip. (2) Jangan gulung kripto sendiri — CryptoKit sudah menyediakan primitif aman; gunakan AES-GCM (authenticated), bukan mode manual. (3) Hashing untuk integritas/fingerprint, bukan untuk password (untuk password gunakan mekanisme server + salt). (4) Kripto klien melengkapi, bukan menggantikan, keamanan server (M15).

10Network Framework & Latihan

Untuk deteksi konektivitas & koneksi low-level (di bawah URLSession). Paling umum: NWPathMonitor untuk memantau status jaringan (menyambung offline mode M12).

import Network

final class ConnectivityMonitor {
    private let monitor = NWPathMonitor()
    private let queue = DispatchQueue(label: "net.monitor")
    var onChange: ((Bool) -> Void)?

    func start() {
        monitor.pathUpdateHandler = { [weak self] path in
            self?.onChange?(path.status == .satisfied)   // online / offline
        }
        monitor.start(queue: queue)
    }
    func stop() { monitor.cancel() }
}
Kapan pakai apaURLSession (M5/M10) untuk HTTP — default. NWPathMonitor untuk deteksi online/offline (memicu sync queue M12). URLSessionWebSocketTask untuk WebSocket (chat/notifikasi live). NWConnection mentah hanya untuk protokol kustom TCP/UDP (jarang di app bisnis). Koneksi LAN (mis. temukan device di jaringan lokal) butuh NSLocalNetworkUsageDescription + Bonjour service.

EX 01

Sync tanpa server

ABK templates harus tersinkron antar iPhone & iPad milik terapis, tanpa Anda mengelola server. Pendekatan?

▸ Lihat solusi & review

SwiftData + CloudKit private DB (cloudKitDatabase: .automatic). Cek accountStatus(); bila tak login iCloud, degradasi ke lokal + beri tahu user. Sync eventual — jangan asumsikan instan.

Review: CloudKit memakai kuota iCloud user, jadi gratis untuk Anda & privat untuk mereka. Uji skenario tanpa iCloud & sync tertunda.

EX 02

Enkripsi data sensitif lokal

Anda perlu menyimpan blob data sensitif terenkripsi di device. Bagaimana dengan CryptoKit + di mana kuncinya?

▸ Lihat solusi & review

AES-GCM (AES.GCM.seal) untuk enkripsi authenticated. Kunci: SymmetricKey disimpan di Keychain, atau gunakan SecureEnclave untuk kunci yang tak pernah keluar hardware. Jangan hardcode kunci.

Review: Keamanan kripto = kekuatan penyimpanan kunci. AES-GCM authenticated mencegah tampering. Ini melengkapi, bukan menggantikan, keamanan server.

EX 03

CIContext boros

App edit foto lag & memori membengkak saat menerapkan filter ke banyak gambar. Apa penyebab umum & fix?

▸ Lihat solusi & review

Membuat CIContext baru per-gambar (mahal). Fix: buat satu CIContext & reuse. Offload filter dari main thread (@concurrent, M3). Downsample sebelum filter untuk thumbnail (M15).

Review: CIContext adalah objek berat GPU — instansiasi sekali. Sambungan langsung ke disiplin performa M15.

EX 04

HealthKit "kosong"

Query langkah HealthKit mengembalikan kosong. Apakah aman menyimpulkan user tak punya data langkah?

▸ Lihat solusi & review

Tidak. Demi privasi, HealthKit tak memberi tahu apakah izin baca ditolak — query hanya mengembalikan kosong. "Kosong" bisa berarti ditolak ATAU benar-benar tak ada data. Rancang UI yang tak menghukum ketiadaan data; jelaskan cara memberi izin di Settings > Privacy > Health.

Review: Model privasi HealthKit unik — ketidaktahuan status baca disengaja. Jangan bangun logika yang mengandalkan pembedaan itu.

11Quiz, Mini-Project, Challenge & Referensi

Quiz Cepat

Jawab dulu di kepala, lalu buka jawaban.

Q1

CloudKit sync

Apa yang harus dicek sebelum mengandalkan sync CloudKit?

▸ Jawaban

Status akun iCloud (accountStatus) — user mungkin tak login; degradasi ke lokal. Sync bersifat eventual (jangan asumsikan instan). Untuk kasus sederhana, SwiftData+CloudKit .automatic lebih ringkas daripada CloudKit API langsung.

Q2

CryptoKit key storage

Di mana kunci kripto disimpan, dan kenapa AES-GCM?

▸ Jawaban

Kunci di Keychain atau Secure Enclave (private key tak keluar hardware) — tak pernah hardcode/UserDefaults. AES-GCM adalah authenticated encryption (mencegah tampering). Jangan gulung kripto sendiri.

Q3

CIContext

Kenapa CIContext harus dibuat sekali dan dipakai ulang?

▸ Jawaban

CIContext adalah objek GPU berat; membuatnya per-gambar boros memori & lambat. Instansiasi sekali, reuse; offload pemrosesan dari main thread; downsample untuk thumbnail.

Mini-Project

Bangun: fitur sistem terintegrasiPilih dua: sync SwiftData+CloudKit (cek accountStatus), enkripsi blob sensitif (AES-GCM, kunci di Keychain), atau peta multi-lokasi (MapKit + MKDirections dengan debounce). Bungkus di balik protocol. Tujuan: integrasi framework sistem dengan disiplin keamanan/performa.

Challenge

Naik levelTambahkan NWPathMonitor untuk memicu sinkronisasi saat online kembali (menyambung offline mode M12) dan tangani konflik CloudKit. Tantangan: alur data online/offline yang tangguh.

Common Mistakes

  • Mengandalkan CloudKit tanpa cek accountStatus (user tak login iCloud).
  • Hardcode kunci kripto / menyimpan di UserDefaults.
  • Membuat CIContext baru per-gambar (boros).
  • Geocoding/directions per-keystroke tanpa debounce (rate limit).
  • Mengasumsikan sync CloudKit instan (padahal eventual).
