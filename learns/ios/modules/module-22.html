01Vision — Analisis Gambar

Vision menganalisis gambar: OCR (baca teks), barcode/QR, deteksi wajah, rectangle, dan menjalankan model Core ML pada gambar. Pola: buat request → jalankan lewat handler → baca observations.

OCR — baca teks dari gambar (mis. struk)
import Vision

func recognizeText(in cgImage: CGImage) async throws -> [String] {
    try await withCheckedThrowingContinuation { cont in
        let request = VNRecognizeTextRequest { req, err in
            if let err { cont.resume(throwing: err); return }
            let lines = (req.results as? [VNRecognizedTextObservation] ?? [])
                .compactMap { $0.topCandidates(1).first?.string }
            cont.resume(returning: lines)
        }
        request.recognitionLevel = .accurate
        request.recognitionLanguages = ["id-ID", "en-US"]   // dukung ID + EN
        let handler = VNImageRequestHandler(cgImage: cgImage, options: [:])
        do { try handler.perform([request]) } catch { cont.resume(throwing: error) }
    }
}
Barcode / QR
let barcodeRequest = VNDetectBarcodesRequest { req, _ in
    let codes = (req.results as? [VNBarcodeObservation] ?? [])
        .compactMap { $0.payloadStringValue }
    // codes: isi barcode/QR
}
API klasik vs Swift baruContoh di atas memakai API klasik (VNRecognizeTextRequest + handler) yang stabil & terdokumentasi luas. Versi iOS terbaru memperkenalkan Vision Swift API baru yang lebih idiomatik (struct request + async). Keduanya valid; verifikasi nama tipe & ketersediaan terhadap dokumentasi Apple untuk iOS target Anda sebelum memilih — jangan asumsikan satu gaya tersedia di semua versi. Offload pemrosesan dari main thread (M3); untuk banyak gambar, downsample dulu (M15).
Kasus vertikal — scan struk/KTPE-commerce/UMKM: user memotret struk → Vision OCR mengekstrak total & tanggal; verifikasi identitas → OCR KTP. Semua on-device: data sensitif tak pernah dikirim ke server (defense-in-depth, selaras doktrin security-first Anda). Bungkus Vision di balik protocol TextRecognizer (M9) agar testable & dapat ditukar.

02VisionKit — Scanner Siap-Pakai

VisionKit memberi UI scanner jadi: DataScannerViewController (pindai teks/barcode live dari kamera) dan VNDocumentCameraViewController (pemindai dokumen multi-halaman dengan auto-crop).

import VisionKit

// Live text & barcode scanning
func makeScanner() throws -> DataScannerViewController {
    guard DataScannerViewController.isSupported,
          DataScannerViewController.isAvailable else { throw ScanError.unavailable }
    return DataScannerViewController(
        recognizedDataTypes: [.text(), .barcode()],   // apa yang dipindai
        qualityLevel: .balanced,
        isHighlightingEnabled: true)
}
// delegate: dataScanner(_:didAdd:allItems:) → terima item terdeteksi realtime
// Butuh izin kamera (M19) + NSCameraUsageDescription
Kapan VisionKit vs VisionVisionKit = UI scanner instan (live scan, pemindai dokumen) — hemat waktu, UX konsisten Apple. Vision = kontrol penuh atas pemrosesan gambar yang sudah Anda miliki (tanpa UI). Untuk "user scan sesuatu sekarang", pakai VisionKit. Untuk "proses gambar yang diunggah/dipotret", pakai Vision. Cek isSupported/isAvailable — tidak semua device mendukung DataScanner.

03Core ML — Menjalankan Model On-Device

Core ML menjalankan model machine learning (klasifikasi gambar, prediksi, dll.) langsung di perangkat. Xcode meng-generate kelas Swift dari file .mlmodel/.mlpackage.

import CoreML
import Vision

// Pola umum: Core ML model dijalankan lewat Vision untuk input gambar
func classify(_ cgImage: CGImage, model: VNCoreMLModel) async throws -> String? {
    try await withCheckedThrowingContinuation { cont in
        let request = VNCoreMLRequest(model: model) { req, err in
            if let err { cont.resume(throwing: err); return }
            let top = (req.results as? [VNClassificationObservation])?.first
            cont.resume(returning: top?.identifier)
        }
        let handler = VNImageRequestHandler(cgImage: cgImage)
        do { try handler.perform([request]) } catch { cont.resume(throwing: error) }
    }
}

// Model non-gambar: pakai kelas ter-generate langsung
// let output = try model.prediction(input: ...)
Ukuran & pembaruan modelModel besar menaikkan ukuran app. Pertimbangkan on-demand resources atau unduh model saat runtime + cache. Core ML memakai Neural Engine bila tersedia (cepat, hemat daya) — set MLModelConfiguration.computeUnits. Untuk memperbarui model tanpa rilis app, unduh .mlmodel baru & kompilasi runtime (MLModel.compileModel(at:)). Verifikasi kompatibilitas format model terhadap versi Core ML target.

04Create ML (Overview)

Create ML adalah alat melatih model kustom — dijalankan di Mac (app Create ML atau framework), bukan di device. Anda memberi data berlabel; ia menghasilkan .mlmodel untuk dipakai Core ML.

// Dijalankan di Mac (mis. Swift Playground / CLI), BUKAN di app iOS
import CreateML

let data = try MLImageClassifier.DataSource.labeledDirectories(at: trainingURL)
let classifier = try MLImageClassifier(trainingData: data)
try classifier.write(to: outputModelURL)   // hasil: .mlmodel → dipakai di app via Core ML
Kapan relevanCreate ML tepat untuk model domain-spesifik sederhana (klasifikasi gambar/teks/tabular) tanpa keahlian ML mendalam — mis. mengklasifikasi kategori produk dari foto. Untuk kebutuhan kompleks, tim ML melatih model (Core ML Tools mengonversi dari PyTorch/TensorFlow). Sebagai solo founder, Create ML memberi jalur cepat "model kustom" tanpa infrastruktur training. Ini overview; kedalaman training di luar cakupan workshop iOS.

// Sentimen (skor -1..1)
let tagger = NLTagger(tagSchemes: [.sentimentScore])
tagger.string = review

nerTagger.string = text
nerTagger.enumerateTags(in: text.startIndex..<text.endIndex, unit: .word,
    scheme: .nameType, options: [.omitWhitespace]) { tag, range in
    if let tag { /* .personalName / .placeName / .organizationName */ }
    return true
}
Kasus vertikal — analisis review & pencarianE-commerce: skor sentimen otomatis pada review produk (moderasi/prioritas). NLEmbedding memberi pencarian semantik ("kemeja" ≈ "baju") on-device. 06Speech — Pengenalan Suara

Speech mengubah ucapan menjadi teks (SFSpeechRecognizer) — dari audio live atau file. Butuh dua izin: Speech Recognition + Mikrofon (M19).

import Speech

// 1. Izin (WAJIB: NSSpeechRecognitionUsageDescription + NSMicrophoneUsageDescription)
func requestSpeechAuth() async -> Bool {
    await withCheckedContinuation { cont in
        SFSpeechRecognizer.requestAuthorization { status in
            cont.resume(returning: status == .authorized)
        }
    }
}

// 2. Kenali dari audio live (ringkas)
let recognizer = SFSpeechRecognizer(locale: Locale(identifier: "id-ID"))
let request = SFSpeechAudioBufferRecognitionRequest()
request.requiresOnDeviceRecognition = true   // privasi: proses di device bila didukung
// pasang audio engine tap → request.append(buffer)
// recognizer?.recognitionTask(with: request) { result, error in ... transkrip ... }
On-device & aksesibilitas ABKSet requiresOnDeviceRecognition = true agar audio tidak dikirim ke server Apple (privasi; tersedia untuk locale/model yang didukung). Untuk vertikal ABK, input suara adalah jalur aksesibilitas penting bagi anak yang kesulitan mengetik — pasangkan dengan umpan balik multi-indera (M17). Locale id-ID mendukung Bahasa Indonesia; verifikasi dukungan on-device untuk locale target. Hentikan recognition saat selesai (baterai, M15).

07Best Practice Lintas-Framework

  • On-device dulu — coba Vision/NL/Speech/Core ML sebelum memanggil server AI; lebih privat, cepat, murah, offline-capable.
  • Offload dari main thread — inferensi berat via @concurrent (M3); jangan bekukan UI (M15).
  • Bungkus di balik protocol — TextRecognizer, Classifier, SpeechTranscriber (M9) → testable, dapat ditukar, mock di test (M13).
  • Perlakukan hasil sebagai probabilistik — OCR/klasifikasi/sentimen bisa salah; sediakan koreksi manual & tangani confidence rendah.
  • Privasi & manifest — data sensitif (KTP, suara) diproses on-device; deklarasikan pemakaian di Privacy Manifest bila relevan (M18).
  • Cek ketersediaan — isSupported/locale/Neural Engine bervariasi antar-device; degradasi anggun (M19).
Epistemik — API ML bergerak cepatFramework AI/ML Apple berevolusi tiap tahun (Vision Swift API baru, model system, dsb.). Nama tipe, ketersediaan locale, dan format model dapat berubah antar versi iOS/Xcode. Verifikasi terhadap dokumentasi Apple & WWDC terkini saat mengimplementasi — contoh di modul ini menunjukkan pola stabil, tetapi konfirmasikan detail untuk iOS target Anda.

08Latihan

EX 01

On-device atau server?

Untuk tiap fitur, on-device (Vision/NL/Speech) atau butuh server/LLM: (a) baca total dari foto struk; (b) deteksi bahasa review; (c) menjawab pertanyaan kompleks pelanggan; (d) transkrip voice note.

▸ Lihat solusi & review

(a) Vision OCR on-device. (b) Natural Language on-device. (c) Server/LLM (reasoning kompleks). (d) Speech on-device (requiresOnDeviceRecognition).

Review: Default on-device untuk OCR/klasifikasi/deteksi/transkrip — privat & murah. Naik ke server hanya untuk reasoning yang model on-device tak mampu.

EX 02

Abstraksi Vision

Anda memakai VNRecognizeTextRequest langsung di ViewModel. Kenapa keliru & bagaimana memperbaiki?

▸ Lihat solusi & review

Vision bocor ke presentation → sulit di-test & ditukar. Perbaiki: definisikan protocol TextRecognizer { func recognize(_ image: CGImage) async throws -> [String] }; implementasi Vision di data layer; ViewModel bergantung pada protocol; mock di test.

Review: Sama seperti networking (M10) — framework adalah detail implementasi di balik boundary domain (M8/M9).

EX 03

Privasi scan KTP

Fitur verifikasi memotret KTP. Bagaimana memastikan sesuai doktrin security-first?

▸ Lihat solusi & review

Proses OCR on-device (Vision) — data KTP tak dikirim ke server. Kirim hanya hasil terverifikasi minimal yang dibutuhkan (bukan foto mentah). Deklarasikan pemakaian di Privacy Manifest (M18); simpan sementara di memori, jangan tulis ke disk tanpa enkripsi (CryptoKit + Keychain, M21/M15).

Review: On-device processing = minimisasi data = defense-in-depth. Kirim data mentah sensitif ke server bila tak perlu adalah kesalahan desain.

EX 04

Hasil probabilistik

OCR total struk kadang salah baca "8" jadi "3". Bagaimana desain UX yang bertanggung jawab?

▸ Lihat solusi & review

Tampilkan hasil OCR sebagai draf yang dapat diedit, bukan final; minta konfirmasi user untuk nilai kritis (jumlah uang); manfaatkan confidence (topCandidates) untuk menandai bagian ragu. Jangan pernah memproses transaksi dari OCR tanpa verifikasi.

Review: Output ML probabilistik — perlakukan sebagai bantuan, bukan kebenaran. Human-in-the-loop untuk nilai kritis (selaras workflow review Anda).

09Quiz, Mini-Project, Challenge & Referensi

Quiz Cepat

Jawab dulu di kepala, lalu buka jawaban.

Q1

On-device vs server

Untuk OCR struk, deteksi bahasa, dan reasoning kompleks — mana on-device, mana server?

▸ Jawaban

OCR (Vision) & deteksi bahasa (Natural Language) on-device — privat, cepat, murah, offline. Reasoning kompleks → server/LLM. Default on-device untuk OCR/klasifikasi/NLP/speech; naik ke server hanya bila model on-device tak mampu.

Q2

Hasil probabilistik

Kenapa output OCR/klasifikasi tak boleh dipercaya mutlak?

▸ Jawaban

Model bersifat probabilistik & bisa salah (mis. '8' terbaca '3'). Untuk nilai kritis (uang, identitas), tampilkan sebagai draf yang dapat diedit + konfirmasi user (human-in-the-loop). Manfaatkan confidence/topCandidates.

Q3

Privasi Speech

Bagaimana menjaga privasi saat speech-to-text?

▸ Jawaban

Set requiresOnDeviceRecognition = true agar audio tak dikirim ke server (untuk locale yang didukung). Butuh izin Speech + Mikrofon. Hentikan recognition saat selesai (baterai).

Mini-Project

Bangun: scan struk on-deviceBuat fitur: potret struk → Vision OCR (id-ID/en-US) mengekstrak total & tanggal, ditampilkan sebagai draf yang dapat diedit. Bungkus Vision di balik protocol TextRecognizer. Tujuan: AI on-device + privasi + hasil probabilistik yang benar.

Challenge

Naik levelTambahkan analisis sentimen review (Natural Language) dan input suara (Speech, on-device) sebagai jalur aksesibilitas. Tantangan: pilih on-device vs server secara sadar per fitur; jaga data sensitif tetap di device.

Common Mistakes

  • Mengirim gambar KTP/struk mentah ke server padahal OCR bisa on-device.
  • Vision/Speech bocor ke ViewModel (bukan di balik protocol).
  • Memproses transaksi dari OCR tanpa konfirmasi user.
  • Speech tanpa requiresOnDeviceRecognition (audio ke server).
  • Tak mengecek isSupported/locale (degradasi tak anggun).
