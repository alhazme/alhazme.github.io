01Foundation (Deep)

Foundation menyediakan primitif yang Anda pakai tiap hari. Beberapa yang sering salah dipakai:

TipeGunakan untukCatatan

Anti-pattern umum(1) Manipulasi path file dengan string concatenation ("\(dir)/\(name)") — rapuh; gunakan API URL. (2) NotificationCenter sebagai pengganti arsitektur (event bus untuk segalanya) — sulit dilacak; batasi ke notifikasi sistem (keyboard, lifecycle). (3) Menyimpan angka satuan tanpa konteks unit — pakai Measurement agar konversi & lokalisasi benar (sambung M17).

02FileManager & Sandbox

App iOS berjalan dalam sandbox. Pilih direktori sesuai sifat data — ini menentukan backup, pembersihan sistem, dan App Review.

DirektoriUntukDi-backup?Bisa dihapus sistem?
DocumentsData user yang dibuat & tak bisa dibuat ulangYaTidak
Application SupportData app (DB, file dukungan)YaTidak
CachesData yang dapat dibuat ulangTidakYa (saat storage menipis)
tmpSementaraTidakYa (kapan saja)
 
import Foundation

enum FileStore {
    static func supportDir() throws -> URL {
        let url = try FileManager.default.url(for: .applicationSupportDirectory,
            in: .userDomainMask, appropriateFor: nil, create: true)
        return url
    }
    static func write(_ data: Data, to name: String) throws {
        let url = try supportDir().appending(path: name)
        try data.write(to: url, options: [.atomic, .completeFileProtection]) // enkripsi at-rest
    }
}
Keamanan & App Review(1) Gunakan .completeFileProtection untuk data sensitif — file terenkripsi saat device terkunci (defense-in-depth, M15). (2) Jangan taruh cache/data yang dapat dibuat ulang di Documents — Apple menolak app yang menyalahgunakan Documents/iCloud backup. (3) Kredensial/token bukan di file — pakai Keychain (M5). (4) Tulis atomik (.atomic) agar tak korup saat interupsi.

03Tanggal & Format — Sumber Bug Klasik

Penanganan tanggal salah adalah bug produksi paling umum. Aturan: simpan UTC/ISO8601, tampilkan lokal (sambung M17).

import Foundation

// SIMPAN / TRANSPORT: ISO8601 (stabil, tak tergantung locale)
let iso = ISO8601DateFormatter()
let stamp = iso.string(from: .now)            // "2026-07-04T09:12:00Z"
let parsed = iso.date(from: stamp)

// TAMPILKAN ke user: Date.FormatStyle (modern, locale-aware, otomatis WIB)
let shown = Date.now.formatted(
    .dateTime.day().month(.wide).year().hour().minute())
// "4 Juli 2026 pukul 16.12" untuk locale id-ID

// Uang / angka: jangan format manual
let harga = 150000.formatted(.currency(code: "IDR"))   // "Rp150.000"
Aturan tanggal & angka(1) Jangan pakai DateFormatter dengan pola string ("yyyy-MM-dd") untuk transport — gunakan ISO8601DateFormatter. (2) DateFormatter mahal dibuat — cache instance-nya bila dipakai berulang. (3) Untuk tampilan, Date.FormatStyle / .formatted() modern menangani locale, zona waktu, & kalender otomatis — jangan rakit string tanggal manual. (4) Uang: Decimal + .currency(code:), jangan Double untuk perhitungan finansial (presisi, relevan fintech Anda).

04Core Foundation (Overview)

Core Foundation adalah lapisan C di bawah Foundation (CFString, CFArray, CFDictionary, dll.). Di Swift modern Anda jarang menyentuhnya langsung.

Kapan masih relevan(1) Toll-free bridging: banyak tipe CF otomatis "menjembatani" ke Foundation (CFString ↔ String) — Anda memakainya tanpa sadar. (2) API C/legacy tertentu (mis. beberapa API Keychain, Core Graphics, Core Text) mengembalikan tipe CF — Anda mem-bridge ke Swift. (3) Manajemen memori CF manual (CFRetain/CFRelease) hampir tak pernah diperlukan di Swift (ARC menangani via bridging). Best practice: tetap di Foundation/Swift; sentuh CF hanya saat API memaksanya, lalu bridge secepatnya ke tipe Swift. Ini overview — kedalaman CF di luar kebutuhan app bisnis modern.

05Contacts

Framework Contacts membaca/menulis kontak via CNContactStore. Butuh izin — kecuali Anda memakai CNContactPickerViewController (picker sistem, tanpa izin, mirip PHPicker M19).

import Contacts

// Dengan izin: baca kontak (mis. cari teman yang pakai app)
func fetchContacts() async throws -> [CNContact] {
    let store = CNContactStore()
    let granted = try await store.requestAccess(for: .contacts)  // NSContactsUsageDescription wajib
    guard granted else { throw ContactError.denied }

    let keys = [CNContactGivenNameKey, CNContactPhoneNumbersKey] as [CNKeyDescriptor]
    let request = CNContactFetchRequest(keysToFetch: keys)
    var result: [CNContact] = []
    try store.enumerateContacts(with: request) { contact, _ in result.append(contact) }
    return result
}
Picker tanpa izin (utamakan ini)Bila hanya butuh satu kontak yang dipilih user (mis. "pilih penerima"), pakai CNContactPickerViewController — tanpa izin, karena user memilih eksplisit. Sama seperti PHPicker untuk foto (M19): pilih permukaan yang tak butuh akses penuh bila memungkinkan. Minimisasi izin = privasi + friksi lebih rendah + App Review lebih mulus. Untuk sinkronisasi massal (CRM), baru minta akses penuh dengan penjelasan jelas.

06EventKit

EventKit mengakses kalender & reminder via EKEventStore. Model izin berubah signifikan di iOS 17: kini terpisah full access vs write-only.

import EventKit

func addBooking(title: String, start: Date, end: Date) async throws {
    let store = EKEventStore()
    // iOS 17+: write-only cukup untuk SEKADAR menambah event (privasi lebih baik)
    let granted = try await store.requestWriteOnlyAccessToEvents()
    guard granted else { throw CalendarError.denied }

    let event = EKEvent(eventStore: store)
    event.title = title
    event.startDate = start
    event.endDate = end
    event.calendar = store.defaultCalendarForNewEvents
    try store.save(event, span: .thisEvent)
}
Izin EventKit (baru & mudah salah)Sejak iOS 17, Apple memisah: write-only (hanya menambah event — butuh NSCalendarsWriteOnlyAccessUsageDescription) vs full access (baca+tulis — NSCalendarsFullAccessUsageDescription). Reminder punya NSRemindersFullAccessUsageDescription. Prinsip least-privilege: jika hanya menambah booking ke kalender, minta write-only — jangan minta full access. String Info.plist yang salah/absen = crash. Model & nama key ini spesifik versi — verifikasi terhadap dokumentasi Apple untuk iOS target Anda.
Kasus vertikal — booking hospitalityUser memesan kamar/meja → tambahkan otomatis ke kalender mereka (write-only, tanpa membaca kalender pribadi mereka = privasi terjaga). Untuk reminder pembayaran/check-in, EventKit Reminders. Bungkus di balik CalendarService protocol agar domain tak tahu EventKit.

07FileProvider (Overview)

FileProvider mengekspos dokumen app Anda ke Files app (dan app lain) — atau mengintegrasikan penyimpanan cloud kustom ke sistem file iOS. Diimplementasikan sebagai extension.

Dua kebutuhan berbeda(1) Ekspos dokumen app ke Files — sering cukup dengan UISupportsDocumentBrowser/LSSupportsOpeningDocumentsInPlace di Info.plist + Document-Based App, tanpa FileProvider penuh. (2) File Provider Extension penuh — saat Anda membangun penyedia penyimpanan (seperti Dropbox/Drive) yang muncul di Files app dengan sinkronisasi. Untuk mayoritas app bisnis (menyimpan invoice/dokumen agar bisa dibuka di Files), opsi (1) sudah cukup. FileProvider Extension penuh adalah proyek besar tersendiri.
Kapan tidak dipakaiJangan bangun File Provider Extension kecuali produk Anda memang penyedia penyimpanan. Untuk berbagi file ke app lain sesekali, UIActivityViewController (share sheet) atau document picker jauh lebih sederhana. Ini overview; implementasi extension penuh di luar cakupan modul ini — pertimbangkan hanya bila jadi kebutuhan produk inti.

08Best Practice & Latihan

  • Direktori sesuai sifat data — Documents (user, tak-reproducible), Application Support (data app), Caches (reproducible). Salah pilih = ditolak App Review / data hilang.
  • Enkripsi at-rest — .completeFileProtection untuk data sensitif; kredensial di Keychain, bukan file.
  • Tanggal: simpan ISO8601/UTC, tampilkan lokal; uang pakai Decimal + FormatStyle.
  • Least-privilege izin — picker tanpa izin (Contacts/Photos) > akses penuh; EventKit write-only > full access.
  • Bungkus di balik protocol — Contacts/EventKit/FileManager di data layer; domain tak meng-import framework sistem.
  • Tetap di Swift/Foundation — sentuh Core Foundation hanya saat API C memaksa, bridge secepatnya.
EX 01

Pilih direktori

Untuk tiap data, direktori mana: (a) database SwiftData app; (b) thumbnail hasil-unduh yang bisa diunduh ulang; (c) invoice PDF yang dibuat user; (d) file zip sementara saat ekspor.

▸ Lihat solusi & review

(a) Application Support. (b) Caches. (c) Documents. (d) tmp.

Review: Reproducible → Caches/tmp (boleh dihapus sistem). User-created tak-reproducible → Documents. Data app pendukung → Application Support. Salah pilih memicu penolakan App Review atau kehilangan data user.

EX 02

Bug tanggal

Server menerima tanggal berbeda-beda tergantung device user. Penyebab paling mungkin & fix?

▸ Lihat solusi & review

DateFormatter dengan pola string tanpa locale/timezone tetap → hasil bergantung setelan device. Fix: pakai ISO8601DateFormatter (atau set locale = en_US_POSIX + timezone UTC) untuk transport. Tampilan tetap pakai FormatStyle lokal.

Review: Transport = deterministik (ISO8601/UTC); tampilan = lokal. Memisahkan keduanya menghilangkan seluruh kelas bug ini.

EX 03

Izin berlebih

App menambah booking ke kalender user dan meminta full access EventKit. Kenapa keliru & apa yang benar?

▸ Lihat solusi & review

Menambah event hanya butuh write-only (iOS 17+). Meminta full access = akses baca ke seluruh kalender pribadi user tanpa perlu → melanggar least-privilege, menakuti user, berisiko di App Review. Fix: requestWriteOnlyAccessToEvents() + NSCalendarsWriteOnlyAccessUsageDescription.

Review: Minta izin seminimal yang dibutuhkan fungsi. Privasi = kepercayaan = konversi lebih baik.

EX 04

Kontak tanpa izin

Fitur "pilih penerima transfer" perlu satu kontak. Haruskah minta akses Contacts penuh?

▸ Lihat solusi & review

Tidak. Pakai CNContactPickerViewController — user memilih satu kontak eksplisit, tanpa dialog izin & tanpa akses ke seluruh buku alamat. Minta akses penuh hanya untuk sinkronisasi massal.

Review: Sama seperti PHPicker (M19). Utamakan permukaan sistem yang tak butuh izin — privasi + friksi lebih rendah.

09Quiz, Mini-Project, Challenge & Referensi

Quiz Cepat

Jawab dulu di kepala, lalu buka jawaban.

Q1

Direktori sandbox

Data yang dapat dibuat ulang (cache) disimpan di mana, dan kenapa bukan Documents?

▸ Jawaban

Di Caches/tmp (boleh dihapus sistem saat storage menipis — benar untuk data reproducible). Documents untuk data user tak-reproducible yang di-backup; menyalahgunakan Documents menyebabkan penolakan App Review & backup membengkak.

Q2

Tanggal

Kenapa memisahkan format transport (ISO8601) dari display (FormatStyle)?

▸ Jawaban

Transport butuh deterministik lintas device (ISO8601/UTC, tak tergantung locale). Display butuh locale-aware (WIB, kalender). Memisahkan keduanya menghapus seluruh kelas bug tanggal. Uang: Decimal + currency, bukan Double.

Q3

EventKit izin

Untuk sekadar menambah booking ke kalender, izin apa yang benar?

▸ Jawaban

Write-only (iOS 17+: requestWriteOnlyAccessToEvents + NSCalendarsWriteOnlyAccessUsageDescription) — least-privilege, tak membaca kalender pribadi. Full access hanya bila perlu baca.

Mini-Project

Bangun: penyimpanan + kalenderBuat FileStore yang memilih direktori sesuai sifat data + .completeFileProtection untuk data sensitif, dan CalendarService (EventKit write-only) untuk menambah booking. Format tanggal ISO8601 (transport) & FormatStyle (display). Tujuan: fondasi data yang benar + least-privilege.

Challenge

Naik levelTambahkan pemilih kontak tanpa izin (CNContactPicker) untuk fitur 'pilih penerima', dan pastikan uang memakai Decimal di seluruh alur. Tantangan: minimisasi izin di setiap permukaan sistem.

Common Mistakes

  • Menaruh cache di Documents (App Review menolak).
  • DateFormatter pola string untuk transport (hasil bergantung device).
  • Double untuk uang (galat presisi).
  • Minta full access EventKit/Contacts saat write-only/picker cukup.
  • Kredensial di file, bukan Keychain.
