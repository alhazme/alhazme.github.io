01Core Graphics (Quartz 2D)

API menggambar 2D vektor: path, gradient, teks, gambar — dipakai untuk visual kustom yang tak disediakan komponen standar. Di SwiftUI, sering cukup Canvas/Path; Core Graphics langsung dipakai saat butuh kontrol context penuh (mis. generate gambar/PDF).

import UIKit

// Render badge/watermark kustom ke UIImage (off-screen)
func makeBadge(_ text: String, size: CGSize) -> UIImage {
    let renderer = UIGraphicsImageRenderer(size: size)
    return renderer.image { ctx in
        let cg = ctx.cgContext
        cg.setFillColor(UIColor(red: 0.85, green: 0.47, blue: 0.34, alpha: 1).cgColor) // clay
        cg.fillEllipse(in: CGRect(origin: .zero, size: size))
        let attrs: [NSAttributedString.Key: Any] = [
            .foregroundColor: UIColor.white,
            .font: UIFont.boldSystemFont(ofSize: size.height * 0.4)]
        let str = NSAttributedString(string: text, attributes: attrs)
        let bounds = str.boundingRect(with: size, options: .usesLineFragmentOrigin, context: nil)
        str.draw(at: CGPoint(x: (size.width - bounds.width)/2, y: (size.height - bounds.height)/2))
    }
}
Kasus vertikal — chart, watermark, invoice(1) Chart kustom sederhana tanpa dependency (memperluas SVG/Canvas). (2) Watermark/badge pada gambar produk. (3) Menggambar konten invoice PDF (M23) memakai context Core Graphics. Untuk grafik data kompleks, pertimbangkan Swift Charts (framework terpisah) sebelum menggambar manual. Core Graphics mahal bila dipanggil berulang di main thread — cache hasil (M15).

02Core Animation

Sistem layer (CALayer) & animasi di bawah UIKit. SwiftUI/UIKit menganimasikan lewat ini secara otomatis; Anda menyentuhnya langsung untuk kontrol halus (path animation, layer khusus).

import UIKit

// Animasi stroke kustom (mis. loading indicator melingkar)
func animateRing(on layer: CAShapeLayer) {
    let anim = CABasicAnimation(keyPath: "strokeEnd")
    anim.fromValue = 0
    anim.toValue = 1
    anim.duration = 1.2
    anim.timingFunction = CAMediaTimingFunction(name: .easeInEaseOut)
    anim.repeatCount = .infinity
    layer.add(anim, forKey: "ring")
}
Kapan langsung ke Core AnimationUtamakan animasi SwiftUI (withAnimation, .animation) / UIView untuk mayoritas kasus — lebih sederhana & deklaratif. Turun ke CALayer/CAAnimation untuk: animasi path (stroke, morph), efek layer (mask, shadow kustom, gradient animatif), atau performa spesifik. Untuk animasi vektor kompleks siap-pakai, Lottie (M11) sering lebih cepat dari membangun manual. Hormati Reduce Motion (aksesibilitas M17) — kurangi/hilangkan animasi bila user memintanya.

03Metal (Overview)

API GPU low-level untuk rendering & compute berperforma tinggi. Sangat kuat, sangat kompleks — jarang dibutuhkan app bisnis.

Kapan dipakai & kapan tidakDipakai: game, pemrosesan gambar/video real-time kustom, visualisasi data masif, shader efek khusus, ML compute custom. Tidak dipakai: UI biasa, animasi standar, filter gambar (pakai Core Image M21). Untuk kebutuhan efek gambar, Core Image sudah GPU-accelerated di atas Metal — Anda dapat manfaat GPU tanpa menulis Metal. Best practice bagi Anda: hampir tak pernah menulis Metal langsung untuk app e-commerce/hospitality/SaaS; bila muncul kebutuhan berat, evaluasi apakah Core Image/Metal Performance Shaders (siap-pakai) cukup sebelum shader kustom. Ini overview; kedalaman Metal adalah spesialisasi tersendiri di luar cakupan app bisnis.

04SceneKit (Overview)

Framework 3D high-level (scene graph: node, geometry, material, cahaya, kamera). Lebih mudah dari Metal untuk konten 3D.

Posisi & alternatifSceneKit cocok untuk 3D non-AR sederhana (mis. preview produk 3D yang dapat diputar). Namun arah Apple untuk konten 3D & AR modern condong ke RealityKit (bagian 05). Untuk sekadar menampilkan model 3D produk, pertimbangkan QuickLook 3D (preview file USDZ tanpa kode 3D) — jauh lebih sederhana dari membangun scene sendiri. Bangun SceneKit/RealityKit hanya bila butuh interaksi 3D kustom. Verifikasi arah framework terkini; ekosistem 3D/AR Apple berevolusi.

05RealityKit & ARKit (Overview)

ARKit melacak dunia nyata (posisi, permukaan, cahaya); RealityKit me-render & mensimulasikan objek 3D di atasnya. Bersama: Augmented Reality.

Kasus vertikal — "lihat produk di ruangan Anda"Relevansi tertinggi AR untuk vertikal Anda: e-commerce furnitur/dekor — user menempatkan model 3D produk (USDZ) di ruangan via kamera sebelum membeli. Jalur termudah: AR Quick Look — tampilkan file USDZ dengan preview AR bawaan sistem (via QuickLook M23), tanpa menulis ARKit/RealityKit sama sekali. Bangun ARKit/RealityKit kustom hanya bila butuh pengalaman AR interaktif khusus (mis. konfigurator produk). Untuk mayoritas kasus "coba di ruangan", AR Quick Look sudah cukup.
PertimbanganAR menuntut perangkat mumpuni, izin kamera (M19), dan berat baterai/termal. Uji di device nyata (bukan simulator). ROI membangun AR kustom tinggi biayanya — validasi kebutuhan bisnis sebelum investasi. ARKit/RealityKit berkembang cepat tiap tahun; verifikasi kapabilitas terkini.

06GameKit (Overview)

Layanan game: Game Center (leaderboard, achievement, matchmaking, multiplayer). Untuk app bisnis, relevansi utama hanyalah elemen gamifikasi — dan itu pun jarang butuh GameKit penuh.

Kapan & alternatifGameKit penuh untuk game sebenarnya. Untuk gamifikasi app bisnis (poin, badge, papan peringkat loyalty) — biasanya lebih baik dibangun di backend Anda sendiri (kontrol penuh, lintas-platform, terintegrasi data bisnis) daripada mengikat ke Game Center. Gunakan GameKit hanya bila Anda memang ingin integrasi Game Center native (achievement iOS, leaderboard global). Untuk loyalty hospitality Anda, papan peringkat backend + PassKit (M20) lebih tepat. Overview — kedalaman GameKit di luar fokus app bisnis.

07Best Practice & Latihan

  • Abstraksi setinggi mungkin — SwiftUI/UIKit → Core Graphics/Animation → (jarang) Metal/3D/AR. Jangan turun level tanpa kebutuhan nyata.
  • Manfaatkan jalur siap-pakai — Core Image (bukan Metal) untuk filter; AR Quick Look (bukan ARKit) untuk "coba di ruangan"; QuickLook 3D (bukan SceneKit) untuk preview model; Swift Charts untuk grafik.
  • Hormati Reduce Motion — animasi kustom harus menyesuaikan preferensi aksesibilitas (M17).
  • Performa — gambar Core Graphics berulang di-cache; kerja GPU/AR berat menguras baterai/termal (M15); uji AR di device nyata.
  • ROI dulu — Metal/AR/3D kustom mahal; validasi kebutuhan bisnis sebelum investasi engineering.
EX 01

Level yang tepat

Untuk tiap kebutuhan, framework mana: (a) filter kecerahan foto produk; (b) "lihat sofa di ruangan"; (c) loading ring kustom; (d) preview model 3D produk yang bisa diputar.

▸ Lihat solusi & review

(a) Core Image (M21), bukan Metal. (b) AR Quick Look (USDZ via QuickLook), bukan ARKit kustom. (c) Core Animation (CAShapeLayer strokeEnd) atau SwiftUI. (d) QuickLook 3D / SceneKit sederhana.

Review: Setiap kasus punya jalur siap-pakai yang menghindari level rendah. Turun ke Metal/ARKit hanya bila jalur tinggi tak cukup.

EX 02

Over-engineering

Seorang engineer mengusulkan menulis renderer Metal untuk menampilkan galeri gambar produk dengan efek fade. Tanggapan Anda?

▸ Lihat solusi & review

Berlebihan. Galeri + fade dilakukan SwiftUI/UIKit + Core Animation dengan mudah; Core Image bila butuh efek gambar. Metal menambah kompleksitas besar tanpa manfaat di sini. Tolak; arahkan ke abstraksi tinggi.

Review: "Gunakan abstraksi setinggi mungkin." Metal dibenarkan hanya oleh kebutuhan performa/efek yang tak terpenuhi level atas.

EX 03

Gamifikasi loyalty

Klien hospitality ingin papan peringkat poin loyalty lintas iOS & Android. GameKit?

▸ Lihat solusi & review

Tidak. GameKit/Game Center terikat ekosistem Apple — tak lintas-platform & terpisah dari data bisnis. Bangun leaderboard di backend sendiri (poin, tier), tampilkan di kedua platform; kartu di Apple Wallet via PassKit (M20).

Review: Untuk gamifikasi bisnis lintas-platform, backend sendiri memberi kontrol & konsistensi; GameKit hanya untuk integrasi Game Center native.

EX 04

Animasi & aksesibilitas

Animasi ring loading kustom Anda berputar terus. Apa yang wajib dipertimbangkan untuk sebagian user?

▸ Lihat solusi & review

Reduce Motion (M17): sebagian user (termasuk sensitivitas vestibular & sebagian ABK) memerlukan animasi minimal. Cek preferensi (UIAccessibility.isReduceMotionEnabled / environment SwiftUI) dan sediakan alternatif statis/halus.

Review: Animasi kustom tak boleh mengabaikan aksesibilitas. Hormati preferensi sistem selalu.

08Quiz, Mini-Project, Challenge & Referensi

Quiz Cepat

Jawab dulu di kepala, lalu buka jawaban.

Q1

Peta keputusan

Aturan emas memilih layer grafis iOS?

▸ Jawaban

Gunakan abstraksi setinggi mungkin yang memenuhi kebutuhan: SwiftUI/UIKit → Core Graphics/Animation → (jarang) Metal/3D/AR. Turun level hanya bila kebutuhan performa/efek tak terpenuhi di atas.

Q2

Core Image vs Metal

Untuk filter gambar, Metal atau Core Image?

▸ Jawaban

Core Image — sudah GPU-accelerated di atas Metal. Anda dapat manfaat GPU tanpa menulis shader Metal. Metal langsung hanya untuk game/compute berat/efek sangat kustom.

Q3

AR view-in-room

Cara termudah 'lihat produk di ruangan' tanpa menulis ARKit?

▸ Jawaban

AR Quick Look — tampilkan file USDZ dengan preview AR bawaan sistem (via QuickLook). Bangun ARKit/RealityKit kustom hanya untuk pengalaman AR interaktif khusus.

Mini-Project

Bangun: visual kustom + previewBuat badge/watermark kustom dengan Core Graphics (UIGraphicsImageRenderer) untuk gambar produk, dan loading ring dengan Core Animation yang menghormati Reduce Motion. Tujuan: grafis 2D kustom + animasi aksesibel.

Challenge

Naik levelTambahkan preview produk 3D via AR Quick Look (USDZ) tanpa menulis ARKit, dan evaluasi (tolak/terima) usulan memakai Metal untuk galeri sederhana. Tantangan: pilih level yang tepat & hindari over-engineering.

Common Mistakes

  • Menulis Metal untuk hal yang SwiftUI/Core Image bisa (over-engineering).
  • ARKit kustom untuk 'view in room' yang cukup dengan AR Quick Look.
  • GameKit untuk gamifikasi lintas-platform (harusnya backend sendiri).
  • Animasi kustom mengabaikan Reduce Motion.
  • Render Core Graphics berulang di main thread tanpa cache.
